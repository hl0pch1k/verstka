**Любой шаблон PowerPoint и вход в любом виде — план, письмо, документ, база знаний, файлы с данными, одна фраза — на входе; три готовые редактируемые презентации в стиле этого шаблона на выходе, обычно за 1–3 минуты.** Агент из открытых моделей решает, какие нужны слайды и о чём каждый; числа считает и проверяет код, а не модель; вёрстка собирается по правилам самого шаблона; каждое решение и каждое число можно открыть и проверить.

## Что умеет

**Вход — в любом виде.**
- **Шаблон** — любой файл PowerPoint (12 форматов: `.pptx`, `.potx`, `.ppt`, `.odp`, `.thmx` и другие), в том числе нарисованный вручную без макетов. Разбирается один раз, кэшируется по хэшу.
- **Текст и план в любом виде**: «Слайд N. …», нумерованный список, маркеры, письмо коллеге («Сначала — …, потом — …»), тезисы. Пункт — слайд в порядке автора; приветствие и подпись — не слайды; указания вроде «покажи на графике», «нужна таблица» — форма слайда, а не его текст ([`plan_form.py`](verstka/planning/plan_form.py), [`directives.py`](verstka/planning/directives.py)).
- **Документ DOCX или PDF** («Из файла» → «Текст из файла», также `.txt`, `.md`, HTML; `.doc`, `.rtf`, `.odt` — через LibreOffice): заголовки, списки и таблицы читаются как есть ([`documents.py`](verstka/ingest/documents.py)). **Длинный документ** (больше 1 200 слов или 40 абзацев — стенограмма, отчёт) — материал, а не план: он сжимается в 10–15 слайдов выводов, цифра не из документа отбрасывается ([`digest.py`](verstka/planning/digest.py)).
- **Короткая тема** — «Сделай презентацию про интегралы»: агент пишет текст сам по статье Википедии или по базе знаний и проверяет факты по источнику ([`topic_writer.py`](verstka/planning/topic_writer.py)). Математика — настоящие формулы PowerPoint (Office Math) с пояснениями.
- **База знаний** — документы по одному, папкой или `.zip` и ссылки на публичные страницы: локальный поиск (BM25, ничего не уходит наружу), цифры только из документов, источник каждого утверждения — в заметках слайда ([`knowledge/`](verstka/knowledge)).
- **Данные** — CSV, TSV, XLSX, JSON, текст с таблицей — **и брендбук** — PDF-гайдлайн, токены JSON, папка или архив с логотипами, ссылка Figma ([раздел ниже](#вторая-ступень-данные-и-брендбук)).
- **Готовая презентация** — «Улучшить готовую»: её текст читается обратно, вёрстка собирается заново.

**Смысл — важнее украшений.**
- Заголовок — вывод с числом, а не тема («Выручка — на 23% больше, чем в сентябре 2025», а не «Выручка по месяцам»).
- Каждое число и каждая пропорция («6 из 30», «в 2 раза», «вдвое», доли, проценты) сверяются со входом до вёрстки и в готовом PPTX; не сошлось — остаются слова автора ([`proportions.py`](verstka/planning/proportions.py), [`grounding.py`](verstka/planning/grounding.py)).
- «Меньше — лучше» у времени, сроков, затрат, ошибок: «В пределах цели SLA — 1 из 4», а не перевёрнутое «План выполнили 3 из 4» ([`polarity.py`](verstka/data/polarity.py)).
- Финал — вывод или просьба самого входа; «Спасибо за внимание», которого автор не писал, не добавляется.
- Честные подписи: «Было / Стало» и «Сейчас / Цель» по смыслу, оценка — со знаком «≈», голый счёт — с тем, что он считает; число слайдов — из текста, в том числе диапазоном («6–8 слайдов»).

**Оформление — по шаблону.**
- Шаблон читается как набор правил: палитра с ролями цветов, шкала кеглей, сетка и поля, хром, карточки, иконки, правила, написанные на слайдах. Слайды встают на слайды-образцы шаблона, остальное компонуется из его фигур.
- **Три варианта** с разной подачей: структурный, визуальный (крупные цифры), компактный ([`strategies.yaml`](configs/strategies.yaml)).
- **Шрифты**: свой шрифт шаблона не меняется. Шаблону, набранному стандартными шрифтами (Arial, Calibri, Times New Roman, шрифты LibreOffice), подбирается пара «заголовки / текст» из 14 свободных семейств с кириллицей по характеру шаблона, и шрифты встраиваются в PPTX — PowerPoint и LibreOffice набирают ими без установки. Переключатель «Подобрать шрифты» (по умолчанию включён), `--no-pick-fonts` ([`fontpick.py`](verstka/brand/fontpick.py)).
- **Картинки** (Z-Image, открытые веса, ≈ 10B): там, где автор описал место или человек попросил; при включённых изображениях — ещё на слайдах, чей заголовок называет видимый предмет, и не меньше 1 картинки (до 7 слайдов) или 2 (от 8). Картинка встаёт полосой во всю высоту у края слайда, текст рядом; без надписей (готовую картинку смотрит модель зрения и при надписи рисует заново), в палитре шаблона. Пустое место под картинку остаётся только по просьбе человека («место под своё фото»).
- Нативные объекты PowerPoint: диаграммы 12 типов с данными, таблицы, формулы. Экспорт PPTX, PDF и HTML.

**Проверка качества — часть пайплайна.** 70 детерминированных проверок и 3 модельные ([`AUDIT.md`](AUDIT.md)): вёрстка, шаблон, плотность, целостность, содержание и 16 проверок графиков и слайдов с данными. Модельные — «Взгляд дизайнера» (модель смотрит на каждый готовый слайд, неудачный собирается заново) и 11 вопросов Приложения 1 со связностью колоды — **включены по умолчанию**, когда подключена модель. Автоисправление с откатом ухудшений, замечания рамками прямо на слайде.

**Правки — кнопкой и словами.** «Исправить слайд» правит замечание на месте по замеру (контраст, мелкий текст, наезд), иначе отдаёт слайд дизайнеру или другому образцу шаблона ([`seen_fix.py`](verstka/audit/seen_fix.py)). В поле «Ваши правки» и в Помощнике: «переделай полностью», «добавь картинку», «покажи таблицей», «крупнее цифры», «короче», «убери слайд 3», «почему слайд 4 такой», «верни как было»; «этот слайд» — слайд на экране. **Без модели** те же правки выполняют правила, и ответ говорит, что сделано по правилам ([`slide_edit.py`](verstka/planning/slide_edit.py)).

**Модели — открытые, через инференс VK.** Qwen3.8-27B (Apache 2.0, 27,8B) на инференсе VK спрашивается первой; если VK не отвечает, в том же запросе отвечает та же Qwen3.8-27B на Polza, затем Qwen3.6-27B ([`models.vk.yaml`](configs/models.vk.yaml)). Картинки — Z-Image на Polza. Без ключей сервис работает целиком без моделей. Подробно — [MODELS.md](MODELS.md).

**Интерфейс «Слои»** — React, только для компьютера: раскладка рассчитана на 1280 × 900, в окне меньше вся сцена уменьшается целиком. Проверен в Chrome и Safari.

## Вторая ступень: данные и брендбук

**Данные считает и проверяет код, модель понимает вопрос и пишет слова.** Код ([`verstka/data/`](verstka/data)) читает файл, строит профиль (типы и роли колонок, ось времени, пропуски, выбросы), выбирает одну из семи аналитических задач и 2–3 вида визуализации из 14 с причинами, агрегирует большие данные (ряд — к периодам, категорий больше 12 — топ и «Остальные N» подписью, справочник — топ-10 строк) и пишет заголовок-вывод с настоящим числом. Перед показом каждое число и каждое утверждение («впереди», «растёт быстрее всех», «в K из N», цель) пересчитываются по сырым строкам файла ([`verify.py`](verstka/data/verify.py)); не подтвердилось — слайд получает заголовок-описание и причину в «Почему так». Модель делает три дела: понимает цели брифа над настоящими колонками (`goal_reader`, каждую часть проверяет код), пишет связку колоды (`data_storyteller`, числа сверяются с фактами), читает страницы PDF-брендбука (`brandbook_reader`). Вид диаграммы она не выбирает и чисел не считает.

- **Колода-история**: вопрос брифа получает ответ первым; вопрос, на который данные не отвечают, — честное «по данным не посчитано». Данные и база знаний — в одной колоде: пункты плана, которых нет в данных, пишутся по базе.
- **Слайд с данными**: нативная диаграмма или таблица PowerPoint в стиле шаблона, подписи осей с единицами, «Источник: файл». Один и тот же файл даёт один вид на любом шаблоне и в любом формате файла (проверяют тесты).
- **«Почему так»** для слайда с данными: профиль, задача, варианты визуализации с мини-графиками и «почему не он», как посчитано число заголовка; «Пересобрать слайд так» строит слайд другим видом.
- **Брендбук** применяется к копии шаблона: цвета (с защитой контраста), шрифты, логотип; при расхождении по умолчанию важнее брендбук, переключатель «Шаблон» оставляет шаблон как есть.
- **Примеры**: [`examples/data-sales-2026`](examples/data-sales-2026) (7 файлов в 4 форматах, ожидаемые виды — в `SCENARIO.md`), [`examples/data-science-2026`](examples/data-science-2026) (6 файлов другой природы), [`examples/brandbook-vk-cloud`](examples/brandbook-vk-cloud) (условный брендбук: PDF, токены, логотипы). В интерфейсе — «Из файла» → «Пример: данные продаж».

Форматы и пределы: CSV и JSON — до 25 МБ, XLSX — до 4 МБ, текст — до 15 МБ, до 200 000 строк в таблице, до 10 файлов за раз; `.xls`, `.ods`, `.numbers` не читаются (сервис пишет, во что сохранить). Подробно — [ARCHITECTURE.md](ARCHITECTURE.md#данные-вторая-ступень).

## Запуск

Сервис — один процесс `verstka serve` (веб-интерфейс и API) на вашей машине; модели подключаются по API, GPU не нужен. Команды — для Ubuntu 24.04 и macOS; на Windows — внутри WSL 2 с Ubuntu.

**1. Системные программы** — Python 3.11 или 3.12, LibreOffice (картинки слайдов и PDF), poppler (`pdftoppm`), Node.js 20+ (один раз собрать интерфейс), git.

```bash
# Ubuntu 24.04 (Node.js 20 — из NodeSource: в стандартном репозитории 18)
sudo apt-get update && sudo apt-get install -y git python3-venv python3-pip libreoffice-impress poppler-utils
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs

# macOS (Homebrew)
brew install python@3.11 node poppler git && brew install --cask libreoffice
```

**2. Код и зависимости**

```bash
git clone https://github.com/hl0pch1k/verstka.git && cd verstka
python3 -m venv .venv            # на macOS: python3.11 -m venv .venv
source .venv/bin/activate        # в каждом новом окне терминала
pip install --upgrade pip && pip install -e ".[api,dev]"
cd web && npm install && npm run build && cd ..
cp verstka/fonts/Play-*.ttf ~/Library/Fonts/   # только macOS: шрифт шаблонов VK для превью LibreOffice
```

**3. Проверка без ключа и без сети — около 15 секунд**

```bash
verstka generate -t tests/fixtures/tpl_audit/templates/lo_focus.pptx -b examples/briefs/fitness_studio.md -o out/check --no-llm --no-vlm --export all
```

В `out/check/` — три варианта (`structured`, `visual`, `compact`), в каждом `deck.pptx`, `deck.pdf`, `deck.html` и отчёты; в консоли — план и оценка проверки (на этой версии 100 / 100 / 100). Без ключа сервис работает полностью: разбор шаблона, планировщик по структуре текста, детерминированная проверка.

**4. Ключ модели.** `cp .env.example .env` и впишите ключи:

```
VK_INFERENCE_API_KEY=...     # инференс VK (финал): с обоими ключами VK профиль configs/models.vk.yaml включается сам
VK_PROJECT_ID=...
POLZA_API_KEY=...            # Polza.ai: картинки Z-Image и запасной путь, если VK не отвечает; без ключей VK — все модели
```

Ключ Polza — в консоли [polza.ai](https://polza.ai) → «API-ключи» (баланс в рублях: по замерам 20.10 — 4–11 ₽ за три варианта вместе с проверками моделью и «Взглядом дизайнера», плюс 1,40 ₽ за картинку). `.env` не попадает в git. Проверка, что модель отвечает:

```bash
verstka generate -t tests/fixtures/tpl_audit/templates/lo_focus.pptx -b examples/briefs/fitness_studio.md -o out/model_check
python -c "import json; p = json.load(open('out/model_check/structured/run_manifest.json'))['planner']; print(p['planned_by'], p.get('model'))"
```

`agent …` — план составила модель (какая ответила — в `run_manifest.json`); `rules None` — модель недоступна, колода собрана без неё, причина — в консоли.

**5. Веб-интерфейс**

```bash
verstka serve                    # http://127.0.0.1:8000, API — http://127.0.0.1:8000/docs
```

Шаблоны датасета кейса (VK Tech, VK Education, VK WorkSpace) в репозиторий не входят: загрузите их кнопкой «Загрузить свой» или положите папку `Датасет` рядом с репозиторием (`../Датасет`). Порт занят — `--port 8080`; доступ из своей сети — `--host 0.0.0.0` (авторизации нет, только доверенная сеть).

| `VERSTKA_CORS_ORIGINS` | адреса для API из другого источника | сервер разработки Vite |

</details>

## Как проверить

Каждая команда работает без ключа и без сети (`--no-llm --no-vlm`) за 5–20 секунд; уберите эти ключи, чтобы работала модель.

```bash
T=tests/fixtures/tpl_audit/templates/lo_focus.pptx     # незнакомый шаблон LibreOffice из репозитория
verstka generate -t $T -b tests/fixtures/plans/warehouse_email.md -o out/plan --no-llm --no-vlm          # план письмом
verstka generate -t $T -b tests/fixtures/documents/report.docx -o out/docx --no-llm --no-vlm             # документ DOCX (или .pdf)
echo "Сделай презентацию о результатах третьего квартала для правления" > brief.md
verstka generate -t $T -b brief.md --kb tests/fixtures/documents/kb -o out/kb --no-llm --no-vlm          # тема + база знаний
verstka generate -t $T --data examples/data-sales-2026 --brand examples/brandbook-vk-cloud/guideline.pdf \
  -o out/data --no-llm --no-vlm                                                                         # данные + брендбук
verstka generate -t $T -b examples/briefs/fitness_studio.md -o out/plain --no-llm --no-vlm --no-pick-fonts  # шрифты шаблона как есть
```

Другие входы: планы экспертов в разных формах — [`tests/fixtures/plans`](tests/fixtures/plans), готовая презентация для «Улучшить готовую» — [`examples/improve`](examples/improve), брифы — [`examples/briefs`](examples/briefs). Ещё команды: `verstka analyze <шаблон>` (разбор и `gallery.html`), `verstka audit <deck.pptx> -t <шаблон>` (проверка любой колоды), `verstka kb <документы и ссылки>` (база знаний), `verstka generate --config configs/run.example.yaml` (запуск одним конфигом), `verstka checks` и `verstka skills` (реестры).

Рядом с каждой колодой: `outline.json` (план и реестр фактов), `layout_plan.json` (выбор макета с причинами), `audit_report.json` (замечания, исправления, сверка чисел), `run_manifest.json` (версии и хэши скиллов, модель, которая ответила, время по этапам, git-коммит).

**Тесты** (на 20.10.2026):

```bash

pytest tests/integration     # 48 интеграционных: полный пайплайн на шаблонах VK, ЛЦТ и колоде без макетов (нужен датасет)

```

CI на Ubuntu 24.04 ([`linux.yml`](.github/workflows/linux.yml)) на каждую отправку в `main`, `next` и `data-stage2` повторяет «Запуск» по шагам: установка, проверка без ключа, веб-сервис, модульные тесты и тесты интерфейса.

## Как устроено

<p align="center">
  <img src="docs/images/pipeline.svg" width="100%" alt="Как устроен Verstka: шаблон разбирается один раз в manifest.json; агент читает вход и манифест, компилятор сверяет каждое число и пишет outline.json; вёрстка, проверка качества и экспорт в PPTX, PDF и HTML">
</p>

Шаблон разбирается один раз в `manifest.json`: палитра, шкала кеглей, сетка, хром, карточки, типы слайдов-образцов (голосуют эвристики, текстовая модель и модель зрения). Вход любого вида сводится к тексту колоды (план, документ, длинный документ — в выводы, тема — писателем по Википедии или базе знаний, данные — колодой-историей из кода); агент (аналитик, дизайнер на каждый слайд, критик) строит `outline.json`, а компилятор сверяет каждое число и пропорцию со входом. Подбор макета объяснимо ставит каждый слайд на образец шаблона, вёрстка клонирует образец или компонует слайд из фигур шаблона, меряя текст метриками шрифта.

Проверка качества (70 + 3 проверки) идёт после вёрстки, автоисправление перевыбирает макеты и откатывает ухудшения, «Взгляд дизайнера» пересобирает неудачные слайды; замечания и просьбы из чата возвращаются к агенту, и он переделывает только нужный слайд с той же сверкой чисел. Промпты и параметры — отдельными версионированными файлами ([`skills/`](skills) — 27 скиллов, [`agents/`](agents), [`configs/`](configs)); версии и sha256 скиллов, модель и конфиг каждого запуска — в `run_manifest.json`. Без модели каждый шаг заменяется детерминированным, и это записывается. Подробно: [ARCHITECTURE.md](ARCHITECTURE.md) · [MODELS.md](MODELS.md) · [AUDIT.md](AUDIT.md).

```
verstka/   ingest (файлы, документы) · analysis (шаблон) · planning (агент, план, смысл, писатель) · knowledge (база знаний)
           data, brand (вторая ступень) · matching · rendering · audit · export · images · api · providers · fonts
skills/  agents/  configs/   промпты, агенты, модели, стратегии — отдельными файлами
web/       интерфейс «Слои»: React + TypeScript + Vite
examples/  брифы, демо-презентации, данные продаж и университета, брендбук VK Cloud, колода для «Улучшить готовую»
tests/     модульные и интеграционные тесты, фикстуры (шаблоны, планы, документы, база знаний)
```

## Ограничения

- Интерфейс — только для компьютера; Firefox и Яндекс Браузер не проверялись.
- Текст по короткой теме пишет модель: проверка по статье или базе знаний отбрасывает неподтверждённое, но может пропустить ошибку — результат помечен «Текст писал агент» с источником. Без модели тема пишется только по базе знаний.
- Без модели формулировки проще: заголовки-выводы — из предложений самого текста, цели данных разбирают правила.
- Данные: вид выбирает код из 14; таблица на слайде — до 10 строк; не читаются `.xls`, `.xlsb`, `.ods`, `.numbers`; сложные вопросы (вторая часть двухчастного вопроса, взвешенное среднее, этап воронки с наибольшими потерями) колода может оставить без ответа и говорит об этом.
- Брендбук: PDF-скан без текста читается только моделью; файл `.fig` (локальная копия Figma) читается без Figma и токена — переменные, стили, сетка, логотипы-векторы (проверено на файлах Figma Community и синтетике); ссылка Figma — через REST API с `FIGMA_TOKEN`, проверена на подставленных ответах API.
- Картинки рисует Z-Image на Polza (у инференса VK модели изображений нет), поэтому для них нужен `POLZA_API_KEY`. Инференс VK не сообщает стоимость, расход в `run_manifest.json` для него пуст.
- Превью и PDF рисует LibreOffice: шрифт, которого нет в системе и нет в файле, заменяется. SmartArt, видео и анимации шаблона не разбираются.
- Хранилище файловое, очередь задач — в процессе: сервис рассчитан на одного или нескольких пользователей. Разработка шла на macOS; Linux проверяется в CI.
