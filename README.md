## Вторая ступень: данные и брендбук

Вторая ступень кейса добавляет к шаблону и тексту два входа: **файлы с данными** (CSV, XLSX, табличный JSON, текст с таблицей) и, по желанию, **брендбук** (PDF-гайдлайн, токены JSON, папка или архив с логотипами и слайдами, ссылка Figma). На выходе — те же три редактируемые презентации, в которых каждый файл показан уместным видом. Сервис читает данные, определяет аналитическую задачу, выбирает и ранжирует 2–3 вида визуализации с причинами, готовит данные (агрегирует или разбивает большие), пишет заголовок-вывод с настоящим числом, подписывает оси с единицами и ставит строку «Источник: файл». Брендбук важнее шаблона, если пользователь не выбрал иное.

**Главное решение: данные интерпретирует код, а не модель.** Профиль, задача, ранжирование видов, агрегация и каждое число заголовка считаются детерминированным кодом ([`verstka/data/`](verstka/data)). Поэтому выбор объясним и воспроизводим, он не зависит ни от шаблона, ни от формата файла (оба свойства проверяют тесты). Модель делает два дела. Навык [`data_storyteller`](skills/data_storyteller) пишет связку колоды: название, контекст из текста, итог, следующие шаги, и может сказать заголовок лучше. Навык [`brandbook_reader`](skills/brandbook_reader) уточняет роли цветов и правила по страницам PDF-гайдлайна. Чисел модель не придумывает: каждое число её формулировки сверяется с фактами, посчитанными из файла, и не прошедшая сверку формулировка заменяется детерминированной. Без модели всё работает на детерминированных формулировках ([`MODELS.md`](MODELS.md#данные-и-брендбук-вторая-ступень)). Сам код тоже проверяет себя: до показа каждое число заголовка и подписи пересчитывается по сырым строкам файла ([`data/verify.py`](verstka/data/verify.py)); не подтвердилось — вместо вывода слайд получает заголовок-описание («Выручка по месяцам»), а причина («Вывод не подтвердился проверкой: …») записывается среди доводов «Задачи» в «Почему так».

### Что делает пользователь

На экране «Создать» те же три плиты. Прибавились четыре действия:

- **Файлы с данными.** В плите «02 Текст»: «Из файла» → «Файлы с данными» (файлов можно выбрать несколько) или перетащить файлы на поле. Под полем встаёт панель «Данные» с карточкой каждого файла: природа данных («Временной ряд · 21 строка · 3 колонки») и то, что в них заметно («2 пропуска», «3 выброса», «Не для графика: одни текстовые колонки»). У книги Excel карточка на каждый лист. Текст можно не писать: колода строится и из одних файлов.
- **Цели из текста.** Под полем «Текст» показано, как фразы вроде «покажи рост выручки» или «сравни регионы» повлияют на выбор («покажи рост выручки» → линейный график). Интерфейс только показывает цели; выбор делает сервер ([`data/goals.py`](verstka/data/goals.py)): цель прибавляет балл задаче и виду, но не навязывает то, чего данные не вмещают: причина отказа записывается среди доводов «Задачи» («Цель «…» здесь не подходит: в данных нет оси времени»).
- **Брендбук.** В заголовке плиты «01 Шаблон» кнопка «Брендбук»: PDF-гайдлайн, токены (JSON), папка или архив, ссылка на файл Figma. Разбор идёт шагами (палитра, шрифты, логотипы, правила), затем на плите встаёт карточка с палитрой. Она открывает слой «Брендбук»: палитра, шрифты, логотипы, правила, **расхождения с выбранным шаблоном** и переключатель «При расхождении важнее: Брендбук / Шаблон».
- **Пример одним щелчком.** «Из файла» → «Пример: данные продаж» загружает текст, 7 файлов с данными и брендбук VK Cloud.

«Создать презентацию» собирает колоду как обычно. На экране сборки появляются фаза «Изучаю данные» и роль «Аналитик данных»: по строке на каждый файл — задача, вид и причина.

### Что получается

**Колода-история** ([`data/story.py`](verstka/data/story.py)): обложка → контекст из текста (если он есть) → карточки ключевых показателей → по слайду на файл → «Три главных вывода» → приложения. Файлы идут в логике истории: сначала те, о которых говорит цель текста, затем динамика, сравнение, структура, распределение, взаимосвязь, качество данных; справочники в конце. Число слайдов из текста или параметров соблюдается: первыми уходят приложения и контекст. Три варианта вёрстки получают одну колоду, поэтому вид данных во всех трёх одинаков, а различаются они вёрсткой.

**Слайд с данными.** Заголовок-вывод с числом из файла, настоящая диаграмма или таблица PowerPoint в стиле шаблона (и брендбука) с подписями осей и единицами, строка «Источник: <файл>» и подпись-пояснение. Диаграммы редактируются вместе с данными. Виды: линия, область, столбцы, полосы, гистограмма, круговая, кольцевая, рассеяние, сгруппированные и накопительные столбцы и полосы, карточки показателей, таблица. Пропуски в ряду остаются разрывами линии, а не нулями.

**Что сервис выбрал на примере продаж** (результат на настоящих файлах из [`examples/data-sales-2026/`](examples/data-sales-2026), проверяется тестами):

| Файл | Природа | Задача | Выбранный вид | Заголовок-вывод |
|---|---|---|---|---|
| `Выручка по месяцам.csv` | временной ряд, 21 точка | динамика | линейный график | Выручка выросла на 23% к сентябрю |
| `Регионы.xlsx` | 8 категорий | сравнение | ранжированные горизонтальные столбцы | Москва даёт 41% выручки, Казань растёт быстрее всех |
| `Каналы продаж.json` | 4 доли, сумма 100% | структура | кольцевая диаграмма | Прямые продажи приносят почти половину выручки — 46% |
| `Время ответа поддержки.csv` | 512 значений | распределение | гистограмма, выбросы отдельно | 80% обращений получают ответ за 2 часа |
| `Клиенты.xlsx` | 240 строк × 6 колонок | справочник | таблица из 10 крупнейших строк, остальные 230 — в подписи | Топ-10 клиентов дают 38% выручки |
| `NPS по кварталам.csv` | 8 кварталов, 2 пропуска | динамика с пропусками | линия с разрывами | NPS вырос до 52, за два квартала данных нет |
| `Итоги квартала.txt` | таблица внутри текста | ключевые значения | карточки показателей | Выручка растёт быстрее числа клиентов: +23% против +18% |

**«Подробнее» → «Почему так» для слайда с данными** отвечает на вопрос «почему именно этот график»:

- «Данные» — профиль файла: колонки с типом и ролью, ось времени, метрики, измерения, пропуски, выбросы, как данные подготовлены для слайда;
- «Задача» — какая из семи (динамика, сравнение категорий, структура долей, распределение, взаимосвязь, справочные значения, ключевые значения), цель из текста и причины;
- «Варианты визуализации» — 2–3 вида, лучший по данным первым, с мини-графиками из данных самого слайда: у выбранного причины, у остальных «почему не он» («8 долей — мелкие сектора нечитаемы»);
- «Заголовок-вывод» — ключевое число, как оно посчитано («Сентябрь 2026 к сентябрю 2025: 423 млн ₽ — на 23% больше. Посчитано по колонке «Выручка».») и каким был бы заголовок-описание.

**«Пересобрать слайд так»** стоит под каждым невыбранным видом: слайд собирается заново другим видом (`POST /api/generations/{id}/{вариант}/slides/{n}/rebuild`). Остальные слайды остаются теми же, прежняя версия сохраняется, и «верни как было» работает как после любой правки. То же можно попросить в чате: «на слайде 4 покажи таблицей». Вид, который данным не подходит, сервис не строит и называет причину.

**Данные, которые нельзя показать графиком** (одни тексты, одна строка, все значения разные и чисел нет), получают сообщение вместо графика: в карточке файла, в ленте агента и в «Почему так» («Не для графика: одни текстовые колонки»). Осмысленная таблица без чисел показывается справочной таблицей, остальное пропускается с объяснением.

**Проверка.** Числа заголовка и подписи пересчитываются по сырым строкам ещё до вёрстки (см. выше), а после вёрстки для слайдов с данными работают 10 проверок аудита ([`AUDIT.md`](AUDIT.md#слайды-с-данными-вторая-ступень)): каждое число заголовка и текста сверяется с файлом, значения диаграммы и таблицы — с тем, что слой данных подготовил из файла, у графика есть подписи осей, единицы и источник, диаграмма не перегружена, таблица не длиннее 10 строк.

### Форматы и пределы

| Что | Форматы | Предел |
|---|---|---|
| CSV, TSV | `.csv`, `.tsv`, `.tab`; кодировка (UTF-8, UTF-16, Windows-1251, KOI8-R), разделитель, десятичная запятая, пробелы в тысячах, шапка в две строки, единицы в шапке («Выручка, млн ₽»), строка «Итого» | 25 МБ |
| JSON | массив записей, `{columns, rows}`, «ключ → записи» (ключ — таблица), «категория → число» | 25 МБ |
| Excel | `.xlsx`, `.xlsm`; все листы, объединённые ячейки шапки, даты и проценты по формату ячейки | 4 МБ |
| Текст | `.txt`, `.md`; таблицы Markdown, блоки через табуляцию или «;», колонки из пробелов; текст вокруг таблицы остаётся контекстом | 15 МБ |
| Строки | до 200 000 строк в таблице (у широкой — не больше миллиона ячеек); дальше читаются первые строки, и карточка файла говорит об этом: «Прочитаны первые 200 000 строк из 640 000» | — |
| За один раз | до 10 файлов и 30 таблиц (листов, ключей JSON, таблиц в тексте); в одну презентацию — до 30 наборов | — |

Файлы Excel читаются ячейка за ячейкой, поэтому их предел меньше: книгу побольше сохраните листом в CSV. Старый `.xls`, `.xlsb`, `.ods`, `.numbers`, PDF и картинки не читаются, и сервис пишет по-русски, во что их сохранить. Пределы сервера меняются переменными `VERSTKA_MAX_DATA_MB`, `VERSTKA_MAX_XLSX_MB`, `VERSTKA_MAX_TEXT_MB`; интерфейс заранее проверяет значения по умолчанию. Ошибка чтения — всегда человеческая фраза («Файл пустой», «Не нашёл таблицу в тексте»).

На больших таблицах агрегация не теряет смысла: ряд дольше 36 точек сводится к неделям, месяцам, кварталам или годам (сумма для потоков, среднее для уровней, последнее значение для остатков); категорий больше 12 — топ и «Остальные N»; распределение — гистограмма с 7–12 интервалами (на малых выборках 5–12) по правилу Фридмана — Диакониса, выбросы отдельно; справочник — таблица из 10 крупнейших строк, а число остальных, их сумма и доля стоят в подписи слайда («Остальные 230 клиентов — 2 167 млн ₽, 62%»); таблица, которую агрегация не спасает, — до трёх слайдов по 10 строк.

### Брендбук

| Источник | Что читается |
|---|---|
| Токены JSON | W3C Design Tokens, Tokens Studio, Style Dictionary, плоский JSON и экспорт переменных Figma: цвета с ролями, шрифты, поля |
| PDF-гайдлайн | по тексту: HEX (а без него RGB и CMYK), роли цветов по словам рядом, шрифты и их замена, поля, сетка, место логотипа, правила. С моделью страницы PDF смотрит `brandbook_reader` и уточняет роли и правила; нового цвета он не добавляет (кроме PDF-скана без текста: там цвета читает только модель, и сервис просит проверить HEX) |
| Папка или архив | токены, PDF, тема примера презентации, логотипы SVG и PNG (вариант — по имени или по картинке), палитра с примеров слайдов (только если цветов нет нигде больше) |
| Ссылка Figma | переменные и стили файла через REST API; нужен `FIGMA_TOKEN` в `.env` |

Прочитанное — это `BrandSpec`: цвета с ролями, шрифты заголовков и текста с заменой, логотипы со светлой и тёмной версией, поля, сетка, место логотипа, правила, предупреждения о том, что не прочиталось. Брендбук применяется к **брендированной копии шаблона**: перекрашиваются тема и явные цвета слайдов, макетов и диаграмм (с защитой контраста текста), меняются шрифты, логотип шаблона заменяется логотипом бренда (светлым или тёмным по фону под ним), а если логотипа нет и брендбук задаёт место, логотип ставится туда без столкновений. Копия разбирается как отдельный шаблон, поэтому вёрстка и аудит палитры и шрифтов работают на ней без изменений.

**Приоритет.** По умолчанию при расхождении важнее **брендбук** на любом шаблоне. Переключатель «Шаблон» оставляет шаблон как есть, а бренд только добавляет то, чего в шаблоне нет (стандартная тема офисного пакета, шрифты по умолчанию, логотип). Список расхождений («Шрифт заголовков: шаблон — Play · брендбук — VK Sans Display», с итогом при выбранном приоритете) показывает слой «Брендбук» и карточка «Оформление» на экране результата. Брендбук необязателен: без него колода строится на шаблоне, как раньше.

### Примеры

### Из командной строки

```bash
# колода из данных: файлы, папка (кроме SCENARIO.md и README.md) или список через запятую; текст необязателен
verstka generate -t "../Датасет/VK Tech шаблон.pptx" --data examples/data-sales-2026 -o out/sales

# с текстом и брендбуком (PDF, JSON с токенами, папка, .zip или ссылка Figma); в brief.md — текст с целями,
# например «Итоги продаж VK Cloud за 9 месяцев 2026 года для правления. Покажи рост выручки, сравни регионы,
# что даёт выручку и где узкие места. Данные — в приложенных файлах.»
verstka generate -t "../Датасет/VK Tech шаблон.pptx" -b brief.md --data examples/data-sales-2026 \
  --brand examples/brandbook-vk-cloud/guideline.pdf --brand-priority brand -o out/sales-brand

# проверка без ключа и сети: данные и брендбук читаются кодом, формулировки детерминированные
verstka generate -t tests/fixtures/tpl_audit/templates/lo_focus.pptx --data examples/data-sales-2026 \
  --brand examples/brandbook-vk-cloud/guideline.pdf -o out/data-check --no-llm --no-vlm
```

`--data` (`-d`) можно повторять; `--brand-priority` принимает `brand` (по умолчанию) и `template`; `--slides N` задаёт число слайдов. Те же ключи — `data`, `brand`, `brand_priority` — читает конфиг запуска `--config`. Рядом с вариантами лежит `data_story.json`: планы всех файлов (задача, варианты, факты заголовков) и то, что модель переписала или не приняла. Последняя команда проверена: 9 слайдов в трёх вариантах, оценка проверки 100 у каждого.

Модели для второй ступени подключаются так же, как для первой: при `VK_INFERENCE_API_KEY` и `VK_PROJECT_ID` в `.env` профиль инференса VK ([`configs/models.vk.yaml`](configs/models.vk.yaml)) выбирается сам, иначе работает Polza ([«Шаг 4. Ключ модели»](#шаг-4-ключ-модели)).

## Verstka 3.1 — что нового

- **Интерфейс «Слои».** Весь путь — одна колода плит: «01 Шаблон», «02 Текст», «03 Параметры и запуск», затем «Сборка» и «Результат» ([`web/`](web)). Плиты и слои ездят по одной кривой за 520 мс: «Подробнее» (качество, «Почему так», агент, план, шаблон, файлы), «Мои презентации» и «Шаблоны» выезжают поверх плит. «Помощник» выходит из-под колоды: колода сужается на любом экране, и содержимое плит и слоёв перестраивается вместе с ней, в том же движении. Никаких всплывающих уведомлений: статус стоит строкой рядом с местом действия. Шрифты Manrope и Unbounded, линейные иконки, ширина от 1280 px.
- **Презентация по короткому запросу.** Напишите в поле «Текст» одну фразу — «Сделай презентацию про вторую мировую войну», «сделай презентаицю про интегралы» — и Verstka напишет насыщенный текст колоды сама ([`planning/topic_writer.py`](verstka/planning/topic_writer.py)): найдёт статью Википедии, составит план из 14–26 ключевых фактов, которые учитель или экзаменатор никогда не пропустит, напишет каждый слайд отдельно и параллельно (хронологии, ключевые цифры, формулы, разборы примеров, таблицы, диаграммы), вернёт на слайды пропущенные факты, уберёт повторы и проверит факты — даты, имена, цифры и каждую формулу — по статье. Математические, физические и технические темы — это колода формул с объяснениями: не больше двух слайдов истории, затем определение, свойства, основные формулы, методы, разобранные примеры с ответом и применения, у каждой формулы — пояснение словами. Скиллы [`topic_planner`](skills/topic_planner), [`topic_slide_writer`](skills/topic_slide_writer), [`topic_fact_check`](skills/topic_fact_check); текст виден и правится («Показать текст»).
- **Настоящие математические формулы.** Формула на слайде — это нативное уравнение PowerPoint (Office Math), которое открывается и редактируется в PowerPoint как «Вставка → Уравнение», а для LibreOffice, Google Slides и Keynote в той же фигуре лежит её картинка, набранная по правилам TeX шрифтом STIX Two Math: полноразмерные дроби, большие интегралы с пределами, «lim» с условием под ним ([`rendering/equation.py`](verstka/rendering/equation.py)). Источник — LaTeX (`$\int_a^b f(x)\,dx = F(b) - F(a)$`) или обычная запись («∫ f(x) dx = F(x) + C», «S = πr²»). Одна формула — крупно на карточке шаблона с пояснением и расшифровкой обозначений; несколько — строками или плитками, каждая со своим названием и пояснением, в трёх вариантах по-разному.
- **Картинки без кривых надписей.** Модель изображений рисует буквы и цифры криво, поэтому их на картинках нет: промпт запрещает надписи и предметы с ними (карты, документы, плакаты, циферблаты), а VLM смотрит на каждую готовую картинку и, если видит надпись, рисует её заново, до трёх раз ([`images/text_check.py`](verstka/images/text_check.py), скилл [`image_text_check`](skills/image_text_check)).

## Verstka 3.0 — что нового

- **Взгляд дизайнера.** Модель с компьютерным зрением (Qwen3.8-27B) смотрит на каждый готовый слайд, как арт-директор на вёрстку перед отправкой клиенту: обрезанный текст, слова, разорванные посередине, наложения, тесный или мелкий текст, плохой контраст, перекос и пустоты, пустые рамки, нечитаемые диаграммы. Слайд с серьёзной проблемой Verstka собирает заново — на другом образце шаблона, композицией из его стилей или в стиле другого варианта, — а новая вёрстка остаётся, только если детерминированный аудит не стал хуже, слайд действительно изменился и модель, сравнив обе вёрстки рядом, выбрала новую дважды — когда новая стояла первой и когда второй: выбор по месту картинки или перепутанные картинки не проходят. Живые прогоны 07.10: на «Классике» модель нашла и исправила пустую строку сетки под плашкой, сетку 2×2 с пустой половиной слайда и обрезанный текст — то, чего не видит ни одна проверка по XML. Финальный прогон на 8 шаблонах: модель пересобрала 11 слайдов (пустоты и перекос, наложения, лишние рамки, разорванные слова) — каждый раз выбрав новую вёрстку в обоих порядках сравнения. Всё — в ленте агента («Взгляд дизайнера: слайд 6 — пустоты и перекос → собрал заново …»), в отчёте аудита и в `run_manifest.json` (`eyes`). Модуль [`audit/eyes.py`](verstka/audit/eyes.py), скиллы [`slide_design_review`](skills/slide_design_review), [`slide_design_compare`](skills/slide_design_compare), настройки [`configs/eyes.yaml`](configs/eyes.yaml). Проверка одного варианта идёт, пока собирается следующий: +40–60 с к сборке и около 3 ₽. На карточке «Взгляд дизайнера» результата и в «Подробнее» → «Качество» — пересобранные слайды «было / стало» рядом, со словами модели.
- **Улучшить готовую презентацию.** Второй путь, о котором говорили организаторы: загрузите старую презентацию — «Из файла» → «Улучшить готовую» в плите «02 Текст». Она становится и шаблоном, и текстом: каждый слайд читается обратно в формате «Слайд N» — заголовок (и заголовок КАПСОМ, и надпись над ним), текст в порядке чтения колонок и карточек, списки, таблицы, диаграммы с данными всех рядов (диаграмма и таблица её данных), SmartArt, код, плитки «число — подпись», заметки докладчика; картинки (и в плейсхолдерах, с кадрированием автора, EMF/WMF — через LibreOffice) сохраняются и встают в улучшенной колоде на свои места; колонтитулы, логотипы, номера страниц, нумерация шагов и скрытые слайды отбрасываются ([`ingest/deck_text.py`](verstka/ingest/deck_text.py)). Проверено на 102 колодах, ни одного сбоя. Тексты остаются как есть, вёрстка собирается заново в трёх вариантах, модель смотрит на каждый слайд, а заметка над полем «Текст» называет оценку проверки исходной презентации («Оценка исходной презентации — N из 100») — её можно сравнить с оценкой новой колоды на экране результата. Ту же старую презентацию можно перенести в другой шаблон: выберите его после загрузки.
- **Все модели — через Polza.ai** (Qwen3.8-27B, запасная Qwen3.6-27B, изображения Z-Image): один ключ, оплата в рублях, расход каждой сборки в рублях — в `run_manifest.json`.
- **Места под изображения в любом тексте.** «[Место под изображение: …]» работает и в тексте без «Слайд N»: пометка не становится текстом слайда, место встаёт рядом с тем, о чём написано.

## Коротко

- **Шаблон читается как набор правил.** Разбирается каждый слайд-образец, а не только макеты: палитра с ролями цветов, шкала кеглей, сетка и поля, хром (логотипы, колонтитулы), карточки, группы повторов, иконки и иллюстрации, правила оформления, написанные прямо на слайдах. Подходят шаблоны, нарисованные вручную на пустых слайдах без макетов.
- **Любой шаблон.** Принимаются 12 форматов: PowerPoint (`.pptx`, `.potx`, `.pptm`, `.potm`, `.ppsx`, `.ppsm`, `.ppt`, `.pot`, `.pps`), темы Office (`.thmx`) и OpenDocument (`.odp`, `.otp`). Регрессионный корпус из **87 чужих шаблонов** (Google Slides, SlidesCarnival, темы Office, LibreOffice, синтетические 4 : 3, 16 : 10 и 26,67″) — **261 колода со средней оценкой 99 из 100**.
- **Агент из открытых моделей ≤ 35B** (Qwen3.8-27B, запасная Qwen3.6-27B; Apache 2.0). Аналитик читает бриф, дизайнер продумывает каждый слайд отдельно, критик проверяет план, компилятор сверяет цифры. Ход работы виден в интерфейсе в реальном времени.
- **Ни одного выдуманного числа.** Каждое число плана сверяется с брифом до вёрстки, готовый PPTX — ещё раз после неё: текст, таблицы, значения диаграмм. Производные (доли, суммы, рост, цена за единицу) помечаются отдельно.
- **Три варианта вёрстки** с разными осями: структурный, визуальный и компактный.
- **Проверка качества — часть пайплайна:** 52 детерминированные проверки (все 24 пункта Приложения 1, ещё 18 сверх них и 10 для слайдов из файлов с данными) и 3 модельные (взгляд дизайнера на каждый готовый слайд — с пересборкой неудачных, 11 вопросов ТЗ по картинке слайда, связность колоды). Автоисправление с откатом, замечания прямо на слайде, исправление на выбор.
- **Данные и брендбук (вторая ступень).** Файлы CSV, XLSX, JSON и текст с таблицей превращаются в колоду-историю: код профилирует данные, выбирает аналитическую задачу и 2–3 вида визуализации с причинами, пишет заголовок-вывод с числом из файла; «Пересобрать слайд так» строит слайд другим видом. Брендбук (PDF, токены, папка, Figma) применяется к копии шаблона и важнее шаблона, если не выбрано иное. [Подробнее](#вторая-ступень-данные-и-брендбук).
- **Чат с агентом.** «На слайде 5 покажи это крупными цифрами», «убери слайд 3», «почему слайд 4 такой», «верни как было».
- **PPTX с редактируемыми объектами** внутри пакета самого шаблона (мастера, макеты, тема, шрифты сохраняются), плюс PDF и HTML (текст — текстом, таблицы — `<table>`, диаграммы — SVG). Все 9 демо-колод проходят проверку схем OOXML.
- **Быстро и без зависимости от сети.** 12 слайдов в трёх вариантах: около 2 минут с моделью и «Взглядом дизайнера» (финальный живой прогон 07.10 на 8 шаблонах: 106–133 с, оценки 94–100), 10–25 секунд без неё. Запасная модель (Qwen3.6-27B) и полностью офлайн-режим.
- **3 845 автотестов:** 3 801 модульный и 44 интеграционных, плюс 662 теста веб-интерфейса.

### 3. Три варианта

Одинаковое содержание, разная подача. Ось различий выбрана так, чтобы варианты отвечали разным задачам показа ([`configs/strategies.yaml`](configs/strategies.yaml)):

- **Структурный.** Одна мысль на слайд, блоки текста и шаги, диаграмма и пункты рядом, точные таблицы.
- **Визуальный.** Крупные цифры-выноски вместо пунктов, цитаты, макеты экранов, кольцевые диаграммы с итогом в центре, фирменная графика и тёмный фон шаблона; от каждого абзаца — его первое предложение.
- **Компактный.** Плотный текст в колонках, вывод первой строкой, данные справа, сравнения таблицами; светлая обложка, когда она есть в шаблоне.

У каждого варианта своя обложка из образцов шаблона, и для одного и того же слайда варианты берут разные образцы.

![Два слайда «Интеграла» в трёх вариантах: структурный, визуальный, компактный](docs/images/variants.jpg)

### Изображения внутри слайдов

Задача со звёздочкой: картинки генерирует модель с открытыми весами не больше 20B — Z-Image от Tongyi-MAI (Apache 2.0, около 10B вместе с кодировщиком текста). Она работает через Polza по тому же ключу, что и модели текста, 1,40 ₽ за изображение.

- **Что рисуется.** Только места, которые автор описал в тексте: «[Место под изображение: экран панели управления теплицей]». Описание становится промптом. С моделью текста его переводит на английский скилл `image_prompt`. В промпт входят цвета палитры шаблона и запрет на надписи.
- **Что не рисуется.** Место под собственное фото автора («Фото я добавлю самостоятельно», «не заполняй сгенерированным изображением») остаётся пустым. Сгенерировать туда можно только своей командой.
- **Палитра.** Готовая картинка мягко сводится к палитре шаблона: тени — к тёмному цвету, полутона — к акценту, света — к светлому. Доля «своих» цветов записывается.
- **Встраивание.** Картинка обрезается точно под пропорции места: без искажения, со скруглением рамки, под элементами, которые лежат поверх. Описание изображения записывается в его альтернативный текст.
- **Варианты.** Все три варианта получают одну картинку на место.
- **Без ключа** места остаются свободными, как раньше.

Не понравилась картинка — карточка «Изображение» рядом со слайдом:
- «Заменить» — с описанием, какая картинка нужна («вид сверху, больше зелени»), или без него;
- «Убрать» — место остаётся под своё фото;
- «Вернуть как было» — как у исправления слайда: меняется только этот слайд, прежняя версия сохраняется.

То же можно попросить в чате: «замени картинку на слайде 2 на вид сверху». Переключатель «С изображениями» в плите «03 Параметры и запуск» выключает генерацию для одной сборки. Настройки и фразы промпта — в [`configs/images.yaml`](configs/images.yaml).

## Как устроено

<p align="center">
  <img src="docs/images/pipeline.svg" width="100%" alt="Как устроен Verstka: шаблон разбирается один раз в manifest.json; агент (аналитик, дизайнер, критик, правка) читает бриф и манифест, компилятор сверяет каждое число с брифом и пишет outline.json; вёрстка, проверка качества (42 + 3 проверки) и экспорт в PPTX, PDF и HTML">
</p>

Замечания проверки и просьбы из чата возвращаются к агенту: он переделывает только нужный слайд, а сверка чисел и проверка проходят заново.

| Слой | Модуль | Вход → выход | Ключевые решения |
|---|---|---|---|
| Приём файла | [`ingest/`](verstka/ingest) | любой файл → `.pptx` | Тип определяется по содержимому; макросы удаляются; старые форматы переводит LibreOffice; шаблону без слайдов собираются образцы из его макетов |
| Разбор шаблона | [`analysis/`](verstka/analysis) | `.pptx` → `manifest.json` | Палитра с ролями, шкала кеглей, сетка и поля; хром по повторам и по рендерам (логотипы, «зашитые» в фон); группы повторов «карточки × N»; тип слайда голосованием эвристик, LLM и VLM |
| Планирование | [`planning/`](verstka/planning) | бриф + манифест → `outline.json` | Реестр фактов: каждое число с цитатой; дизайнер на каждый слайд; критик и одна правка; сверка с брифом ([`grounding.py`](verstka/planning/grounding.py)) отбрасывает выдуманные числа |
| Данные (вторая ступень) | [`data/`](verstka/data) | файлы с данными + текст → `outline.json` с `SlideData` | Чтение в `Table`, профиль, задача, 2–3 вида с причинами, агрегация, факты, заголовок-вывод — детерминированный код без модели; колода-история; «Пересобрать слайд так» |
| Брендбук (вторая ступень) | [`brand/`](verstka/brand) | брендбук + шаблон → брендированная копия шаблона | Чтение в `BrandSpec` (токены, PDF, папка и архив, Figma); копия с цветами, шрифтами и логотипами бренда разбирается как отдельный шаблон; приоритет «брендбук» или «шаблон» |
| Подбор макета | [`matching/`](verstka/matching) | план + манифест → `layout_plan.json` | Балл каждого образца с причинами и альтернативами; образцы выбираются на всю колоду сразу, чтобы слайды шаблона не повторялись; образец, не вместивший слайд при вёрстке, исключается, и выбор повторяется |
| Вёрстка | [`rendering/`](verstka/rendering) | план → `deck.pptx` | Слайд встаёт на слайд-образец шаблона, если тот его вмещает; диаграммы и таблицы, нарисованные в образце фигурами или картинкой, заменяются настоящими; готовый клон проверяется ([`clone_check.py`](verstka/rendering/clone_check.py): потери, мелкий текст, дыры, наезды и наложения), иначе берётся следующий образец или композиция по дизайн-системе ([`compose.py`](verstka/rendering/compose.py)); текст подбирается по метрикам шрифта; фон под каждым текстом измеряется, цвет берётся из палитры |
| Проверка качества | [`audit/`](verstka/audit) | `deck.pptx` → `audit_report.json` | Промежуточное представление колоды со слоями шаблона; реестр проверок; автоисправление с откатом |
| Экспорт | [`export/`](verstka/export) | `deck.pptx` → PDF, HTML | Один запуск LibreOffice на колоду, варианты параллельно |
| Сервис и интерфейс | [`api/`](verstka/api), [`web/`](web) | — | FastAPI с задачами и SSE, React; чат-агент |

Подробно, со всеми правилами для чужих шаблонов: [`ARCHITECTURE.md`](ARCHITECTURE.md).

**Воспроизводимость.** Любая правка промпта меняет sha256 скилла. Версии и хэши скиллов, модели, конфиг и git-коммит попадают в `run_manifest.json` каждой генерации. Ответ модели валидируется по JSON-схеме с повторами. Если модель недоступна, шаг заменяется детерминированным запасным вариантом, и это тоже записывается.

Паспорт каждого запуска виден в интерфейсе («Подробнее» → «Файлы»): кто составил план и какой моделью, время по этапам, итог проверки, версии всех скиллов и агентов — и совпадают ли они с текущими.

| Категория | Проверок | Примеры |

## Модели

Все три модели — через [Polza.ai](https://polza.ai): один ключ, оплата в рублях.

| Роль | Модель | Лицензия | Размер |
|---|---|---|---|
| текст, план и проверка по картинке — основная | Qwen3.8-27B — та же модель, что даёт инференс VK | Apache 2.0 | 27,8B |
| то же — запасная | Qwen3.6-27B | Apache 2.0 | 27,8B |
| изображения внутри слайдов | Z-Image (Tongyi-MAI) | Apache 2.0 | 6,15B + кодировщик 4B |

Если основная модель не может ответить (лимит Polza на модель, сбой всех её хостов), запрос сразу уходит запасной, а состояние обеих видно в интерфейсе. Для финала — Qwen3.8-27B на инференсе VK ([`configs/models.vk.yaml`](configs/models.vk.yaml)). Подробности, цены и где какая модель используется: [`MODELS.md`](MODELS.md).

## Ограничения

- Интерфейс рассчитан на десктоп; мобильная вёрстка не делалась.
- Превью и PDF рисует LibreOffice: шрифт шаблона, которого нет в системе, заменяется. В самом PPTX шрифты шаблона сохраняются, а для русского текста шрифт без кириллицы заменяется близким по классу.
- Ширина текста считается по метрикам встроенных шрифтов и поправочным коэффициентам для остальных, поэтому подгонка текста консервативна.
- Без модели планировщик опирается на структуру брифа (разделы, перечисления, числа, таблицы Markdown); свободный текст без структуры лучше планирует модель.
- SmartArt, видео и анимации шаблона не разбираются, слайды с ними не используются как образцы.
- Изображения генерируются только для мест, которые автор описал в тексте. Слайды без такой заметки картинку не получают: вместо неё — иконки и иллюстрации самого шаблона.
- Модели работают только через Polza.ai: нужен ключ, баланс в рублях (по оценке 3–5 ₽ за три варианта, около 3 ₽ за «Взгляд дизайнера» и 1,40 ₽ за изображение) и доступ к polza.ai. У Polza минутный и дневной лимиты запросов к каждой модели: при лимите основной отвечает запасная, при лимите обеих колода собирается без модели. Без ключа — офлайн-режим.
- Данные (вторая ступень): вид визуализации выбирает код по профилю данных из 14 видов, модель его не выбирает и чисел не считает. Три варианта вёрстки показывают данные одним видом и различаются вёрсткой. Не читаются `.xls`, `.xlsb`, `.ods` и `.numbers` (сохраните как `.xlsx` или CSV); в таблице — до 200 000 строк, дальше читаются первые; книга Excel — до 4 МБ. Таблица на слайде — не больше 10 строк, остальное уходит в подпись или на следующие слайды (до трёх).
- Брендбук (вторая ступень): PDF-скан без текста читается только моделью; файл `.fig` прочитать нельзя, вместо него — ссылка Figma или токены JSON. Чтение Figma по ссылке проверено на подставленных ответах REST API (`tests/unit/test_brand_folder_figma.py`), живой файл Figma не проверялся; переменные файла API Figma отдаёт на тарифе Enterprise, стили читаются без них. Логотип шаблона, нарисованный текстом или автофигурой, не распознаётся как логотип: он остаётся, а бренд ставит свой по правилу места из брендбука.
- Хранилище файловое, очередь задач — в процессе: сервис рассчитан на одного или нескольких пользователей, а не на продакшен-нагрузку.
- Сервис разрабатывался на macOS. На Linux установка, генерация без ключа, веб-сервис и модульные тесты проверяются в GitHub Actions на Ubuntu 24.04 ([`linux.yml`](.github/workflows/linux.yml)); для Linux есть отдельная настройка шрифтов LibreOffice. На Windows запускайте сервис в WSL 2.
- Постоянного стенда нет: у команды нет подходящего сервера для постоянной работы сервиса. Сервис запускается на любой машине по разделу [«Запуск»](#запуск), его работа показана в [видео](docs/video/README.md).

## Запуск

Verstka — самостоятельный сервис: веб-интерфейс и API работают в одном процессе `verstka serve` на вашей машине, открытые модели подключаются по API. GPU не нужен.

> **Постоянного сервера у команды нет.** Поэтому у прототипа нет публичного адреса. Сервис запускается на любой машине по инструкции ниже, на чистой машине это около 15 минут. Работа сервиса целиком показана в [видео](docs/video/README.md). Установка, проверка без ключа, веб-сервис и модульные тесты по этой инструкции проверяются при каждом изменении кода на Ubuntu 24.04 в GitHub Actions ([`linux.yml`](.github/workflows/linux.yml)).

Ниже семь шагов. Команды — для Linux (Ubuntu 24.04) и macOS. На Windows установите WSL 2 с Ubuntu и выполняйте команды для Ubuntu внутри неё.

### Шаг 1. Системные программы

| Программа | Зачем |
|---|---|
| Python 3.11 или 3.12 | сам сервис |
| LibreOffice | картинки слайдов, PDF, превью шаблонов |
| poppler (`pdftoppm`) | картинки слайдов из PDF |
| Node.js 20 или новее | один раз собрать веб-интерфейс |
| git | скачать код |

**Ubuntu 24.04:**

```bash
sudo apt-get update
sudo apt-get install -y git python3-venv python3-pip libreoffice-impress poppler-utils
```

Из стандартного репозитория Ubuntu 24.04 ставится Node.js 18, а сборка интерфейса проверяется на 20. Поставьте Node.js 20 из репозитория NodeSource:

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

**macOS** (через [Homebrew](https://brew.sh)):

```bash
brew install python@3.11 node poppler git
brew install --cask libreoffice
```

Проверьте, что всё на месте: каждая команда должна напечатать версию.

```bash
python3 --version     # 3.11.x или 3.12.x (на macOS: python3.11 --version)
node --version        # v20 или новее
soffice --version     # LibreOffice; на macOS: /Applications/LibreOffice.app/Contents/MacOS/soffice --version
pdftoppm -v
```

### Шаг 2. Код и зависимости

```bash
git clone https://github.com/hl0pch1k/verstka.git
cd verstka
python3 -m venv .venv            # на macOS: python3.11 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e ".[api,dev]"
cd web && npm install && npm run build && cd ..
```

`source .venv/bin/activate` включает окружение сервиса. В каждом новом окне терминала его нужно включать снова, находясь в папке `verstka`.

**Только на macOS:** LibreOffice для macOS видит лишь установленные шрифты. Установите шрифт Play из репозитория, иначе превью шаблонов VK нарисуются запасным шрифтом. В Linux он подключается сам, в PPTX шрифты шаблона сохраняются в любом случае.

```bash
cp verstka/fonts/Play-*.ttf ~/Library/Fonts/
```

### Шаг 3. Проверка без ключа и без сети — около 10 секунд

```bash
verstka generate -t tests/fixtures/tpl_audit/templates/lo_focus.pptx -b examples/briefs/fitness_studio.md -o out/check --no-llm --no-vlm
```

Шаблон лежит в репозитории, модель не нужна. В консоли появятся план слайдов и оценка проверки качества каждого варианта. В папке `out/check/` будут три варианта (`structured`, `visual`, `compact`), в каждом `deck.pptx` и отчёты. Если так и есть, установка прошла успешно.

Без ключа сервис работает полностью, только в офлайн-режиме: детерминированный разбор шаблона, планировщик по структуре текста и детерминированная проверка качества. С моделью формулировки живее, а сложные тексты раскладываются по слайдам точнее.

### Шаг 4. Ключ модели

Модели не запускаются на вашей машине: сервис обращается к открытым моделям через [Polza.ai](https://polza.ai) — OpenAI-совместимый API с оплатой в рублях. Один ключ даёт все три модели: Qwen3.8-27B, запасную Qwen3.6-27B и Z-Image для изображений. Одна генерация трёх вариантов стоит по оценке 3–5 ₽, «Взгляд дизайнера» — около 3 ₽, плюс 1,40 ₽ за каждое изображение.

**Как получить ключ Polza:**

1. Зарегистрируйтесь на [polza.ai](https://polza.ai) и войдите в консоль. Пополните баланс (банковская карта, СБП): запросы к моделям платные.
2. Откройте раздел «API-ключи» ([polza.ai/dashboard/api-keys](https://polza.ai/dashboard/api-keys)) и создайте ключ. При желании задайте ему лимит расходов.
3. Скопируйте ключ.

**Куда вписать ключ.** Создайте файл `.env` из примера:

```bash
cp .env.example .env
```

Откройте `.env` в любом текстовом редакторе (например, `nano .env`) и вставьте ключ после знака `=` в строке `POLZA_API_KEY=`:

```
POLZA_API_KEY=ваш_ключ
```

Сохраните файл. `.env` не попадает в git, ключ остаётся только на вашей машине. Сервис читает `.env` при запуске, поэтому после изменения ключа перезапустите `verstka serve`.

На финале по ТЗ обязателен инференс VK. Добавьте в `.env` ключи `VK_INFERENCE_API_KEY` и `VK_PROJECT_ID` — при них профиль VK (`configs/models.vk.yaml`, Qwen3.8-27B, одна модель) выбирается сам, ничего больше менять не нужно. Картинки — Z-Image через Polza (`POLZA_API_KEY` остаётся в `.env`), пока у VK нет своей модели изображений; если её дадут — укажите id в `VK_T2I_MODEL`. Переменная `VERSTKA_MODELS` принудительно выбирает профиль (`configs/models.vk.yaml` или `configs/models.yaml`) и важнее ключей VK. Настройки запросов, лимиты и цены — в [MODELS.md](MODELS.md#сервис-api-и-настройки).

| Переменная | Что задаёт | Если не задана |
|---|---|---|
| `POLZA_API_KEY` | ключ Polza.ai: Qwen3.8-27B, запасная Qwen3.6-27B, изображения Z-Image | работа без моделей, места под изображения свободны |
| `VERSTKA_MODELS` | принудительно выбирает конфиг моделей (`configs/models.vk.yaml` или `configs/models.yaml`), важнее ключей VK | профиль выбирается по ключам: VK при обоих ключах VK, иначе `configs/models.yaml` |
| `VK_INFERENCE_API_KEY`, `VK_PROJECT_ID` | инференс VK (финал, обязателен по ТЗ): при обоих профиль `configs/models.vk.yaml` включается сам | профиль Polza, модели VK выключены |
| `VK_T2I_MODEL` | собственная модель изображений VK; Z-Image через Polza отвечает после неё | в профиле VK изображения рисует Z-Image через Polza |
| `VERSTKA_WORKSPACE` | кэш разобранных шаблонов и генераций; здесь же файлы с данными и брендбуки | `./workspace` |
| `FIGMA_TOKEN` | личный токен Figma (Settings → Security → Personal access tokens) для брендбука по ссылке на файл Figma | ссылка Figma не читается, сервис пишет, что делать; PDF, JSON, папки и архивы читаются без него |
| `VERSTKA_MAX_DATA_MB`, `VERSTKA_MAX_XLSX_MB`, `VERSTKA_MAX_TEXT_MB`, `VERSTKA_MAX_BRAND_MB` | пределы размера файла с данными (CSV, TSV, JSON), книги Excel, текста с таблицей и брендбука, МБ | 25, 4, 15 и 50 |

**Проверка, что модель отвечает** (около минуты):

```bash
verstka generate -t tests/fixtures/tpl_audit/templates/lo_focus.pptx -b examples/briefs/fitness_studio.md -o out/model_check
python -c "import json; p = json.load(open('out/model_check/structured/run_manifest.json'))['planner']; print(p['planned_by'], p.get('model'))"
```

Вторая команда печатает, кто составил план: `agent qwen/qwen3.8-27b` — модель ответила (`qwen/qwen3.6-27b` — ответила запасная). `rules None` — модель недоступна. Генерация в этом случае всё равно завершается без модели, а в консоли выше есть предупреждение с причиной: неверный ключ, нет денег на балансе Polza или хосты модели перегружены.

### Шаг 5. Веб-интерфейс

```bash
verstka serve
```

Откройте в браузере <http://127.0.0.1:8000>. Остановить сервис — `Ctrl+C` в терминале.

1. **«01 Шаблон».** Выберите карточку шаблона на ленте или нажмите плитку «Загрузить свой» — она стоит прямо на ленте, а также в разделе «Все шаблоны»: подойдёт любой файл PowerPoint (`.pptx`, `.potx`, `.ppt`, `.odp` и другие, всего 12 форматов). Новый шаблон разбирается от нескольких секунд до пары минут, в зависимости от числа слайдов, и только один раз: результат кэшируется в папке `workspace/`. По желанию в заголовке плиты — «Брендбук»: PDF-гайдлайн, токены JSON, папка или архив, ссылка Figma ([подробнее](#брендбук)).
2. **«02 Текст».** Вставьте текст презентации, загрузите его кнопкой «Из файла», нажмите «Взять пример» или напишите тему одной фразой. Файлы с данными добавляет «Из файла» → «Файлы с данными» (или перетаскивание на поле); готовый набор — «Пример: данные продаж» ([подробнее](#что-делает-пользователь)). Число слайдов в плите «03 Параметры и запуск» можно задать, а можно оставить заданное в тексте.
3. **«Создать презентацию».** Экран «Сборка»: слева раскладка с эскизами слайдов и таймер от нажатия, справа «Как думает агент». Три варианта готовы через 1–3 минуты.
4. **Результат.** Переключайте варианты справа от слайда и слайды внизу. «Скачать PowerPoint» и «PDF» сохраняют файлы (ссылка «Веб» — в «Подробнее» → «Файлы»). «Помощник» в шапке — чат для правок словами. Карточки под оценкой («Качество», «Как работал агент», «Почему так») и ссылки «План», «Шаблон», «Файлы» открывают лист «Подробнее»: проверку качества, объяснения решений, разбор шаблона и паспорт запуска. «Мои презентации» в шапке хранят все прежние сборки.

Шаблоны датасета кейса (VK Tech, VK Education, VK WorkSpace) в репозиторий не входят. Загрузите их через «Загрузить свой» или положите папку `Датасет` рядом с репозиторием (`../Датасет`) для командной строки и интеграционных тестов.

Документация API (Swagger) — <http://127.0.0.1:8000/docs>. Если порт 8000 занят: `verstka serve --port 8080`. Чтобы открыть сервис с другого компьютера в своей сети: `verstka serve --host 0.0.0.0` и адрес `http://<IP машины>:8000`. Авторизации в сервисе нет, поэтому открывайте его только в доверенной сети.

### Шаг 6. Командная строка

Всё, что умеет интерфейс, доступно и из терминала (окружение включено: `source .venv/bin/activate`).

```bash
# разбор шаблона: workspace/templates/<id>/manifest.json и наглядный gallery.html
verstka analyze "../Датасет/VK Tech шаблон.pptx"

# три варианта с проверкой качества и экспортом во все форматы
verstka generate -t "../Датасет/VK Tech шаблон.pptx" -b examples/briefs/fitness_studio.md -o out/vktech --export all

# воспроизводимый запуск одним конфигом
verstka generate --config configs/run.example.yaml

# проверка любой готовой колоды по правилам шаблона и экспорт
verstka audit out/vktech/structured/deck.pptx -t "../Датасет/VK Tech шаблон.pptx"
verstka export out/vktech/structured/deck.pptx -t "../Датасет/VK Tech шаблон.pptx" --format all

# вторая ступень: колода из файлов с данными и брендбук (подробно — в разделе «Вторая ступень»)
verstka generate -t "../Датасет/VK Tech шаблон.pptx" --data examples/data-sales-2026 \
  --brand examples/brandbook-vk-cloud/guideline.pdf -o out/sales

# реестры скиллов и проверок
verstka skills
verstka checks
```

Шаблоны датасета в репозиторий не входят: положите папку `Датасет` рядом с репозиторием (`../Датасет`) или укажите свой путь.

### Постоянный стенд

У команды нет подходящего сервера для постоянной работы сервиса, поэтому стенд не развёрнут. Для постоянного стенда хватит обычной виртуальной машины с Ubuntu 24.04 без GPU, потому что модели подключаются по API. Установка та же: шаги 1–5. Затем сервис запускается как служба (например, через systemd) командой `verstka serve --host 0.0.0.0 --port 8000` за обратным прокси с HTTPS и авторизацией. Своей авторизации в сервисе нет.
