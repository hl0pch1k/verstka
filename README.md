# Verstka — цифровой дизайнер презентаций

Кейс № 4 хакатона «Лидеры цифровой трансформации 2026» (VK Tech).

Verstka **читает чужой PPTX как набор правил** — дизайн-токены, паттерны слайдов, компоненты, ассеты, правила дизайнера — и собирает по ним новые презентации: три заметно разных варианта вёрстки на один бриф, с аудитом, автоисправлением и экспортом в **PPTX, PDF и HTML**. Сервис не привязан к трём шаблонам из датасета: на входе может быть любой PPTX, в том числе нарисованный вручную на пустых слайдах без макетов.

```
PPTX ─► разбор шаблона ─► manifest.json      бриф ─► план колоды ─► outline.json
                                   └──────────────┬──────────────┘
                              подбор макета ─► layout_plan.json (объяснимо)
                              рендер (клон образца | синтез из токенов) ─► deck.pptx
                              аудит ─► автофикс (≤ 2 итерации) ─► аудит ─► audit_report.json
                              экспорт ─► .pptx  .pdf  .html   + run_manifest.json
```

## Что умеет

| Требование ТЗ | Как закрыто |
|---|---|
| Разбор произвольного шаблона | Единица анализа — слайд-образец, а не макет (в реальных шаблонах 95% фигур свободные). Токены (палитра с ролями, шкала кеглей, сетка, хром), группы повторов «карточки×N», роли слотов, тип слайда (ансамбль: эвристики + LLM + VLM), компоненты, ассеты, правила. Результат виден человеку: `gallery.html` и вкладка «Шаблон» |
| 10–15 слайдов или по запросу | Планировщик с реестром фактов (каждое число — со ссылкой на цитату брифа), «не более N слайдов» парсится из брифа |
| 3 варианта вёрстки | Стратегии `structured`, `visual`, `compact` (`configs/strategies.yaml`): разные инструкции планировщику, веса типов слайдов, плотность |
| Нативные объекты PPTX | Текст, фигуры, таблицы и диаграммы — редактируемые объекты PowerPoint; картинки — только иконки/иллюстрации самого шаблона. Ничего не растеризуется |
| Аудит (Приложение 1) | 24 детерминированные проверки + 2 модельные (11 вопросов ТЗ по картинке слайда, связность колоды). Список: `AUDIT.md`, `verstka checks` |
| Исправления на выбор | Каждое замечание несёт действие автофикса; пользователь применяет все, выбранные или никакие (UI, API, чат) |
| Экспорт .pptx / .pdf / .html | PDF — LibreOffice; HTML — собственный рендерер из структуры слайда: текст текстом, таблицы `<table>`, диаграммы SVG, один файл |
| Версионирование скиллов | `skills/<имя>/skill.yaml` + промпты отдельными файлами, версия и sha256; `run_manifest.json` фиксирует версии скиллов, модели, конфиг, коммит; запуски сравниваются (`/diff`, вкладка «Запуск») |
| Только открытые модели ≤ 35B | `qwen/qwen3.8-27b` (Apache 2.0) через OpenAI-совместимый API; смена на инференс VK — правка `base_url` в одном файле. Подробности: `MODELS.md` |
| ≤ 5 минут на презентацию | Без моделей — 5–10 с на вариант; с моделями — 1–3 мин на три варианта (вызовы параллельны) |

## Требования

- Python 3.11+
- LibreOffice (`soffice`) и poppler (`pdftoppm`) — рендер слайдов для превью, VLM-проверок и PDF
  - macOS: `brew install --cask libreoffice && brew install poppler`
  - Ubuntu: `apt-get install -y libreoffice-impress poppler-utils`
- Node.js 20+ — только для сборки веб-интерфейса

## Настройка моделей

Скопируйте `.env.example` в `.env` и впишите ключ провайдера. Файл `.env` подхватывается автоматически (из текущей папки и из корня репозитория), в git не попадает.

| Переменная | Назначение |
|---|---|
| `OPENROUTER_API_KEY` | ключ OpenAI-совместимого провайдера (по умолчанию OpenRouter, см. `configs/models.yaml`) |
| `VERSTKA_MODELS` | путь к альтернативному `models.yaml` (например, `configs/models.vk.yaml` для инференса VK) |
| `VERSTKA_WORKSPACE` | папка кэша разборов и генераций (по умолчанию `./workspace`) |
| `VERSTKA_FIXTURES_DIR` | папка с шаблонами датасета для интеграционных тестов |

Без ключа сервис работает в **офлайн-режиме**: детерминированный разбор, запасной планировщик, детерминированный аудит. Это режим для тестов и отладки; качество плана и классификации слайдов выше с моделями.

Закрытые API (OpenAI, Anthropic и т. п.) не используются нигде, включая разработку и тесты: тесты работают на `MockProvider`.

## Быстрый старт: веб-интерфейс

```bash
verstka serve
```

Откройте <http://127.0.0.1:8000>. Дальше: «Загрузить шаблон» → вставить бриф (или написать агенту в чат) → «Сгенерировать». Вкладки:

- **Шаблон** — что сервис понял: палитра с ролями, шрифты и шкала кеглей, правила, галерея паттернов с типами и голосами классификаторов.
- **План** — структура колоды по стратегиям, реестр фактов, решение по макету для каждого слайда.
- **Варианты** — слайды трёх вариантов, замечания аудита поверх слайда, «почему такой макет» (причины и альтернативы).
- **Аудит** — оценка, замечания по слайдам, выбор исправлений и их применение.
- **Экспорт** — PPTX, PDF, HTML и все JSON-артефакты.
- **Запуск** — `run_manifest`: версии скиллов, модели, тайминги, сравнение с другим запуском.

Чат-агент понимает обычные фразы: «сделай презентацию на 8 слайдов для совета директоров: …», «почему слайд 4 такой», «покажи аудит», «исправь всё», «экспорт».

Для разработки интерфейса: `verstka serve --reload` и `cd web && npm run dev` (Vite проксирует `/api` на порт 8000).

## Быстрый старт: CLI

```bash
# 1. Разбор шаблона → workspace/templates/<id>/manifest.json + gallery.html
verstka analyze "path/to/template.pptx"

# 2. Три варианта с аудитом, автофиксом и экспортом во все форматы
verstka generate -t "path/to/template.pptx" -b examples/briefs/vk_workspace_feature.md -o out/demo --export all

# То же одной командой из конфига (воспроизводимый запуск)
verstka generate --config configs/run.example.yaml

# Полностью без моделей
verstka generate -t template.pptx -b brief.md -o out/offline --no-llm --no-vlm

# Аудит любой колоды по правилам шаблона; экспорт готового PPTX
verstka audit out/demo/structured/deck.pptx -t template.pptx
verstka export out/demo/structured/deck.pptx -t template.pptx --format all

# Реестры
verstka skills
verstka checks
```

Результат генерации:

```
out/demo/
  structured/ | visual/ | compact/
    deck.pptx  deck.pdf  deck.html
    outline.json        план колоды и реестр фактов
    layout_plan.json    выбранный макет, балл, причины, альтернативы для каждого слайда
    audit_report.json   замечания, применённые исправления, оценка
    run_manifest.json   версии скиллов и их хэши, модели, конфиг, тайминги, git-коммит
    slides/             PNG-рендеры слайдов
```

Бриф — обычный Markdown или текст. Необязательная шапка (`аудитория`, `тип`, `slides`) и фразы вида «не более 8 слайдов» учитываются; таблицы Markdown становятся нативными таблицами и диаграммами. Примеры: `examples/briefs/`.

## API

Swagger: <http://127.0.0.1:8000/docs>. Основное:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/templates` | загрузить PPTX, запустить разбор (возвращает `job_id`) |
| `GET` | `/api/templates/{id}` | манифест шаблона |
| `POST` | `/api/generations` | бриф или готовый outline → три варианта (`job_id`) |
| `GET` | `/api/jobs/{id}/events` | прогресс в реальном времени (SSE) |
| `GET` | `/api/generations/{gid}` | варианты: план, макеты, аудит, файлы, слайды |
| `GET` | `/api/generations/{gid}/{strategy}/explain/{n}` | почему слайд n свёрстан так |
| `POST` | `/api/generations/{gid}/{strategy}/fixes` | применить выбранные или все автоисправления |
| `GET` | `/api/generations/{gid}/{strategy}/diff/{gid2}/{strategy2}` | чем отличаются два запуска |
| `POST` | `/api/chat` | чат-агент |

## Скиллы, агенты и воспроизводимость

```
skills/<имя>/skill.yaml        версия, роль модели (llm|vlm), параметры, схема ответа
skills/<имя>/prompts/*.md      промпты (Jinja2) отдельными файлами
agents/*.yaml                  какие скиллы и в каком порядке использует агент
configs/*.yaml                 модели, стратегии, пороги анализа
```

Любая правка промпта меняет sha256 скилла; версия и хэш попадают в `run_manifest.json` каждой генерации. История — в git. Ответ модели всегда валидируется по JSON-схеме с повторами; при недоступности модели шаг заменяется детерминированным запасным вариантом, и это записывается в манифест.

## Тесты

```bash
pytest                          # модульные + интеграционные (датасет ищется в ../Датасет или $VERSTKA_FIXTURES_DIR)
pytest -m "not integration"     # только модульные, ~20 с
```

Интеграционные тесты прогоняют полный пайплайн на трёх шаблонах VK и на двух «невиданных»: шаблоне ЛЦТ и колоде, нарисованной вручную без макетов.

## Ограничения

- Только десктопный веб; мобильная вёрстка интерфейса не делалась.
- Рендер превью и PDF зависят от LibreOffice: отсутствующие на машине шрифты шаблона заменяются (в самом PPTX шрифты шаблона сохраняются).
- Метрики ширины текста считаются по встроенному шрифту Play (OFL); для других гарнитур используется поправочный коэффициент, поэтому аудит переполнения консервативен.
- SmartArt, видео и анимации шаблона не разбираются; слайды с ними не используются как образцы.
- Генерация изображений (задача со звёздочкой) в текущей версии не включена; в колоду попадают только ассеты самого шаблона.
- Хранилище файловое, очередь задач в процессе: сервис рассчитан на одного-нескольких пользователей, не на продакшен-нагрузку.

## Документы

- `ARCHITECTURE.md` — слои пайплайна, контракты, ключевые решения
- `MODELS.md` — модели, лицензии, размеры, где какая используется, стоимость
- `AUDIT.md` — все проверки аудита и действия автофикса (генерируется из реестра: `python scripts/gen_audit_md.py`)
- `docs/superpowers/specs/` — исходный дизайн-документ
