# Verstka — цифровой дизайнер презентаций

Кейс № 4 хакатона «Лидеры цифровой трансформации 2026» (VK Tech).

Verstka **читает чужой PPTX как набор правил** — дизайн-токены, паттерны слайдов, компоненты, ассеты, правила дизайнера — и собирает по ним новые презентации: три заметно разных варианта вёрстки на один бриф, с аудитом, автоисправлением и экспортом в **PPTX, PDF и HTML**. Сервис не привязан к трём шаблонам из датасета: на входе может быть любой PPTX, в том числе нарисованный вручную на пустых слайдах без макетов.

```
                                   бриф ─► агент: аналитик → дизайнер каждого слайда → критик → правка
                                               → компилятор → сверка цифр с брифом ─► outline.json
PPTX ─► разбор шаблона ─► manifest.json                                  │
                                   └──────────────┬──────────────────────┘
                              подбор макета ─► layout_plan.json (объяснимо)
                              рендер (композиция по дизайн-системе | клон образца) ─► deck.pptx
                              аудит ─► автофикс (≤ 2 итерации) ─► аудит ─► audit_report.json
                              экспорт ─► .pptx  .pdf  .html   + run_manifest.json
```

## Что умеет

| Требование ТЗ | Как закрыто |
|---|---|
| Генерация структуры и текста агентом | Агент (`planning/agent.py`, скиллы `slide_designer`, `design_critic`, `deck_architect`): аналитик читает бриф как структуру (заказанные слайды, диаграммы, таблицы, формулы, правила, ряды данных); дизайнер продумывает каждый слайд отдельным вызовом модели — форму по назначению данных, заголовок-вывод с цифрой, короткий вывод, заметки докладчика, данные диаграммы и две альтернативы для других вариантов; критик проверяет план по брифу и правилам, дизайнер правит отмеченные слайды. Ход работы виден в интерфейсе в реальном времени и сохраняется («Как работал агент», «Почему слайд такой») |
| Презентация по одной теме (эксперимент, выключен) | Режим автора (`planning/writer.py`): текст, где есть только тема («История VK»), агент пишет сам по статье Википедии со ссылками на её предложения и проверкой каждого факта. В сдаваемой версии выключен (`configs/writer.yaml`, включается `VERSTKA_WRITER=1`): короткий текст собирается как есть — каркас, который человек дописывает |
| Чат с агентом | Помощник понимает правки готовой колоды: «на слайде 3 покажи расходы таблицей», «сделай заголовок короче», «убери слайд 5», «поменяй местами 2 и 3», «верни как было». Слайд переделывает тот же дизайнер с той же сверкой цифр; каждая правка сохраняет прежнюю версию варианта (`versions/vN`, `edits.json`) |
| Достоверность | Каждое число плана сверяется с брифом до вёрстки (`planning/grounding.py`), а готовая презентация — ещё раз после неё: проверка `figure_not_in_brief` читает текст, таблицы и диаграммы PPTX и считает посчитанные значения (доли, рост, суммы) отдельно; итог виден на экране результата («Цифры сверены с текстом: 75 чисел, лишних нет») |
| Разбор произвольного шаблона | Единица анализа — слайд-образец, а не макет (в реальных шаблонах 95% фигур свободные). Токены (палитра с ролями, шкала кеглей, сетка, хром), группы повторов «карточки×N», роли слотов, тип слайда (ансамбль: эвристики + LLM + VLM), компоненты, ассеты, правила. Результат виден человеку: `gallery.html` и вкладка «Шаблон» |
| Любой файл шаблона | Загрузка принимает `.pptx`, `.potx`, `.pptm`, `.ppsx`, `.thmx` (тема PowerPoint), старые `.ppt`/`.pot`/`.pps` и `.odp`/`.otp` (`ingest/convert.py`: OOXML перепаковывается, макросы удаляются, старые форматы переводит LibreOffice). Тип файла проверяется по содержимому; PDF, Keynote, Word или архив получают понятный ответ, что загрузить вместо них. Шаблон без слайдов (обычный `.potx`) или с одной обложкой получает образцы из собственных макетов (`ingest/samples.py`) |
| Шаблоны из интернета | Служебные слайды бесплатных шаблонов (Credits, «How to use», Resource page) не становятся образцами; образцовые значения колонтитулов («John Doe», «New York», «2023», адрес сайта шаблона) не попадают в колоду; холст для контента не берётся со слайда с повёрнутым заголовком или с фотографией под текстом; глубокие фирменные цвета (бордо, тёмно-синий) распознаются как акцент. Шрифты без кириллицы (DM Sans, Lato, Barlow, Anton, Cardo…) для русского текста заменяются шрифтом того же класса — из самого шаблона, если в нём есть кириллический, иначе общедоступным (`rendering/cyrillic.py`); вёрстка измеряет текст уже в нём |
| 10–15 слайдов или по запросу | Планировщик с реестром фактов (каждое число — со ссылкой на цитату брифа), «не более N слайдов» и шапка брифа обязательны. Без модели работает детерминированный планировщик, который читает бриф как дизайнер: шаги «Неделя 1: …» → процесс, «Риск: …» → карточки, перечисления → карточки, три и больше чисел → ряд KPI с короткими подписями, таблицы → диаграмма или таблица, заголовок каждого слайда — вывод |
| Вёрстка как у дизайнера | Контентные слайды верстаются по дизайн-системе шаблона (`rendering/compose.py`): одна сетка и один кегль заголовка на колоду, шкала шрифтов шаблона с читаемыми минимумами, карточка самого шаблона (копия фигуры из образцов), крупные числа в одну строку, текст подбирается под место, неразрывные пробелы по правилам русской типографики. Обложка, разделители и финал — клоны образцов с фирменной графикой |
| 3 варианта вёрстки | Стратегии `structured` (повестка, одна мысль на слайд, списки с разделителями, точные таблицы), `visual` (ключевая цифра первым слайдом, карточки с номерами, диаграмма с выводом, фирменная графика шаблона на слайдах с одной мыслью), `compact` (соседние разделы в две колонки, сравнения таблицами, ≥ 8 слайдов) — `configs/strategies.yaml`: инструкции планировщику, веса типов, плотность. Когда бриф сам задаёт форму каждого слайда, варианты различаются подачей: крупные цифры и кольцевые диаграммы с итогом (visual), текст слева и вывод первой строкой (compact) |
| Нативные объекты PPTX | Текст, фигуры, таблицы и диаграммы — редактируемые объекты PowerPoint; картинки — только иконки/иллюстрации самого шаблона. Ничего не растеризуется |
| Аудит (Приложение 1) | 27 детерминированных проверок + 2 модельные (11 вопросов ТЗ по картинке слайда, связность колоды). Список: `AUDIT.md`, `verstka checks` |
| Исправления на выбор | Каждое замечание несёт действие автофикса; пользователь применяет все, выбранные или никакие (UI, API, чат) |
| Экспорт .pptx / .pdf / .html | PDF — LibreOffice; HTML — собственный рендерер из структуры слайда: текст текстом, таблицы `<table>`, диаграммы SVG, один файл |
| Версионирование скиллов | `skills/<имя>/skill.yaml` + промпты отдельными файлами, версия и sha256; `run_manifest.json` фиксирует версии скиллов, модели, конфиг, коммит; запуски сравниваются (`/diff`, вкладка «Запуск») |
| Только открытые модели ≤ 35B | `qwen/qwen3.8-27b` (Apache 2.0) через OpenAI-совместимый API; смена на инференс VK — правка `base_url` в одном файле. Подробности: `MODELS.md` |
| ≤ 5 минут на презентацию | Разбор шаблона — один раз (кэш по хэшу): 1–2 с на XML + рендер превью LibreOffice (≈ 50 с для 37 слайдов шаблона ЛЦТ). Три варианта с аудитом, автофиксом и экспортом PPTX/PDF/HTML без моделей — 8–25 с на шаблон VK; LibreOffice запускается один раз на колоду, варианты экспортируются параллельно. С моделями — 1–3 мин на три варианта |

## Невиданный шаблон

На финале сервис прогонят на шаблоне, которого он не видел, возможно нарисованном вручную на пустых слайдах. Поэтому ничего не завязано на три шаблона датасета — все решения выводятся из самого файла:

- **Хром** (логотипы, колонтитулы, номера) — по повторам на слайдах, по макетам и мастерам и **по рендерам**: логотипы, «зашитые» в фоновые картинки (шаблон ЛЦТ), находятся как контуры, стоящие на одном месте на большинстве слайдов. Заголовок никогда не заходит под логотип.
- **Пустые рамки** (белые карточки без текста, как в ЛЦТ) становятся слотами-контейнерами: в них пишется текст или встаёт таблица/диаграмма.
- **Справочные слайды** (листы иконок и логотипов, палитра HEX, список ссылок, листы графики) распознаются и не используются как макеты; их иконки идут в библиотеку ассетов.
- **Композиция** рисует на «холсте» — самом чистом слайде-образце той же семьи (фон, хром, стиль заголовка сохраняются), а не на голом макете; карточки — копии карточек самого шаблона; плашка под заголовком становится рубрикой раздела, если так устроены образцы; фирменная графика (3D-объекты, рендер в фоне, коллаж) узнаётся по повторам и остаётся сбоку от текста.
- **Группы ячеек** перетекают по пролёту: две карточки из трёх растягиваются, четыре встают вместо трёх; рукописные номера страниц переписываются по новому порядку.
- **Заголовки на плашках** растут вместе с плашкой до ближайшего препятствия; текст в карточке занимает высоту карточки; один кегль для одной роли во всех карточках.
- **Цвет по реальному фону**: градиенты, полупрозрачные свечения и стили фона темы измеряются там, где стоит текст; после раскладки каждый текст проверяет землю под собой и берёт читаемый цвет из палитры шаблона, а не чистый чёрный или белый. Диаграммы подбирают цвета под фон под ними, светлый фирменный цвет затемняется в своём тоне, стандартные акценты тем Office/LibreOffice не берутся, легенда повторяет цвета секторов точно.
- **Шаблоны без текста на слайдах** (LibreOffice `.otp`): цвет заголовка — унаследованный из макета и мастера, поля — по пустым плейсхолдерам, выделение текста из стилей снимается, полупрозрачные «пузыри» — вуаль, по которой идёт текст.

Проверено на корпусе из 87 чужих шаблонов (бесплатные Google Slides / Canva / SlidesCarnival, темы Office, шаблоны LibreOffice, синтетические 4:3 / 16:10 / 26,67″): 261 колода, средняя оценка аудита 99,0, ошибок 9; каждую правку проверяют на всём корпусе, а колоды шаблонов VK сравниваются с эталоном фигура за фигурой.

Контракт обобщаемости проверяется тестом `tests/integration/test_unseen_templates.py` на двух невиданных входах: шаблоне ЛЦТ (37 слайдов, фоны-картинки, Montserrat) и синтетической колоде, нарисованной вручную без плейсхолдеров (`tests/fixtures/handdrawn.py`).

## Валидность файлов

Каждая колода собирается внутри пакета самого шаблона (мастера, макеты, тема, встроенные шрифты сохраняются) и проходит проверку OOXML: схемы XSD, связи, content types, уникальность id, разрешимость `r:embed`. Все 15 контрольных колод (3 шаблона VK, ЛЦТ и ручная колода × 3 стратегии) проходят валидацию `validate.py --original <шаблон>` без новых ошибок. LibreOffice рендерит превью и PDF с копии пакета, у которой очищены подсказки плейсхолдеров макетов, — в самом PPTX ничего не меняется.

## Требования

- Python 3.11+
- LibreOffice (`soffice`) и poppler (`pdftoppm`) — рендер слайдов для превью, VLM-проверок и PDF
  - macOS: `brew install --cask libreoffice && brew install poppler`
  - Ubuntu: `apt-get install -y libreoffice-impress poppler-utils`
- Шрифты шаблонов для превью и PDF. В Linux и Docker встроенный Play (`verstka/fonts/`) подключается к LibreOffice автоматически. LibreOffice для macOS читает только установленные шрифты: без Play превью шаблонов VK рисуются запасным Arial Black, цифры шире и переносятся. Установите Play один раз: `cp verstka/fonts/Play-*.ttf ~/Library/Fonts/`. Для шаблона ЛЦТ нужен Montserrat (Google Fonts, OFL). В самом PPTX шрифты шаблона сохраняются в любом случае, PowerPoint использует встроенные
- Node.js 20+ — только для сборки веб-интерфейса

## Настройка моделей

Скопируйте `.env.example` в `.env` и впишите ключ провайдера. Файл `.env` подхватывается автоматически (из текущей папки и из корня репозитория), в git не попадает.

| Переменная | Назначение |
|---|---|
| `OPENROUTER_API_KEY` | ключ OpenAI-совместимого провайдера (по умолчанию OpenRouter, см. `configs/models.yaml`) |
| `VERSTKA_MODELS` | путь к альтернативному `models.yaml` (например, `configs/models.vk.yaml` для инференса VK) |
| `VERSTKA_WORKSPACE` | папка кэша разборов и генераций (по умолчанию `./workspace`) |
| `VERSTKA_FIXTURES_DIR` | папка с шаблонами датасета для интеграционных тестов |

Без ключа сервис работает в **офлайн-режиме**: детерминированный разбор, детерминированный планировщик (см. «Что умеет»), детерминированный аудит. Девять демо-колод в `examples/outputs/` собраны именно так; с моделями выше качество формулировок и классификации слайдов.

Закрытые API (OpenAI, Anthropic и т. п.) не используются нигде, включая разработку и тесты: тесты работают на `MockProvider`.

## Быстрый старт: веб-интерфейс

```bash
verstka serve
```

Откройте <http://127.0.0.1:8000> (интерфейс для экрана ноутбука, от 1280 px). Два экрана, понятных без инструкции:

1. **Создать** — «① Выберите шаблон» (обложки разобранных шаблонов и плитка «Свой шаблон»: нажать или перетащить файл — `.pptx`, `.potx`, `.ppt`, `.odp` и другие), «② О чём презентация» (текст в свободной форме или из файла, «Вставить пример», сколько слайдов, для кого) и одна кнопка «Создать презентацию». Тип презентации, варианты оформления и модель — в «Дополнительных настройках»; черновик текста сохраняется сам.
2. **Результат** — во время сборки: этапы простыми словами, прогресс каждого варианта и таймер. После: три варианта оформления, крупный слайд и лента миниатюр под ним (клик по слайду — полноэкранный просмотр, ← → листают, Esc закрывает), «Скачать PowerPoint» и PDF, оценка «Проверка качества». «Мои презентации» в шапке — все прошлые сборки с обложками и оценками.

Всё экспертное — в выдвижной панели **«Подробнее»**: проверка качества (замечания по слайдам, автоисправление), «почему слайд такой» (выбранный макет, причины, альтернативы), план и реестр фактов, что понято из шаблона (палитра с ролями, шрифты и шкала кеглей, сетка, макеты слайдов с голосами классификаторов, правила), файлы всех вариантов и паспорт запуска (`run_manifest`: версии скиллов, модели, тайминги, сравнение запусков).

Кнопка **«Помощник»** в правом нижнем углу открывает чат. Он понимает обычные фразы — «сделай презентацию на 8 слайдов для совета директоров: …», «почему слайд 4 такой», «покажи план», «проверь качество», «исправь всё» — и сам открывает нужное.

Для разработки интерфейса: `verstka serve --reload` и `cd web && npm run dev` (Vite проксирует `/api` на порт 8000).

## Быстрый старт: CLI

```bash
# 1. Разбор шаблона → workspace/templates/<id>/manifest.json + gallery.html
verstka analyze "path/to/template.pptx"

# 2. Три варианта с аудитом, автофиксом и экспортом во все форматы
verstka generate -t "path/to/template.pptx" -b examples/briefs/vk_workspace_feature.md -o out/demo --export all

# То же одной командой из конфига (воспроизводимый запуск)
verstka generate --config configs/run.example.yaml

# Полностью без моделей
verstka generate -t template.pptx -b brief.md -o out/offline --no-llm --no-vlm

# Аудит любой колоды по правилам шаблона; экспорт готового PPTX
verstka audit out/demo/structured/deck.pptx -t template.pptx
verstka export out/demo/structured/deck.pptx -t template.pptx --format all

# Реестры
verstka skills
verstka checks
```

Результат генерации:

```
out/demo/
  structured/ | visual/ | compact/
    deck.pptx  deck.pdf  deck.html
    outline.json        план колоды и реестр фактов
    layout_plan.json    выбранный макет, балл, причины, альтернативы для каждого слайда
    audit_report.json   замечания, применённые исправления, оценка
    run_manifest.json   версии скиллов и их хэши, модели, конфиг, тайминги, git-коммит
    slides/             PNG-рендеры слайдов
```

Бриф — обычный Markdown или текст. Необязательная шапка (`аудитория`, `тип`, `slides`) и фразы вида «не более 8 слайдов» учитываются; таблицы Markdown становятся нативными таблицами и диаграммами. Примеры: `examples/briefs/`.

## API

Swagger: <http://127.0.0.1:8000/docs>. Основное:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/templates` | загрузить шаблон (`.pptx`, `.potx`, `.pptm`, `.ppsx`, `.thmx`, `.ppt`, `.odp`…), запустить разбор (возвращает `job_id`) |
| `GET` | `/api/templates/{id}` | манифест шаблона |
| `POST` | `/api/generations` | бриф или готовый outline → три варианта (`job_id`) |
| `GET` | `/api/jobs/{id}/events` | прогресс в реальном времени (SSE) |
| `GET` | `/api/generations/{gid}` | варианты: план, макеты, аудит, файлы, слайды |
| `GET` | `/api/generations/{gid}/{strategy}/explain/{n}` | почему слайд n свёрстан так |
| `POST` | `/api/generations/{gid}/{strategy}/fixes` | применить выбранные или все автоисправления |

| `POST` | `/api/generations/{gid}/{strategy}/edits` | правка варианта словами: слайд, порядок, «верни как было» (`job_id`) |

## Скиллы, агенты и воспроизводимость

```
skills/<имя>/skill.yaml        версия, роль модели (llm|vlm), параметры, схема ответа
skills/<имя>/prompts/*.md      промпты (Jinja2) отдельными файлами
agents/*.yaml                  какие скиллы и в каком порядке использует агент
configs/*.yaml                 модели, стратегии, пороги анализа
```

Любая правка промпта меняет sha256 скилла; версия и хэш попадают в `run_manifest.json` каждой генерации. История — в git. Ответ модели всегда валидируется по JSON-схеме с повторами; при недоступности модели шаг заменяется детерминированным запасным вариантом, и это записывается в манифест.

## Ограничения

- Только десктопный веб; мобильная вёрстка интерфейса не делалась.
- Рендер превью и PDF зависят от LibreOffice: отсутствующие на машине шрифты шаблона заменяются. В самом PPTX шрифты шаблона сохраняются; для русского текста шрифт без кириллицы заменяется близким по классу.
- Метрики ширины текста считаются по встроенному шрифту Play (OFL); для других гарнитур — поправочный коэффициент (Montserrat 1.2, Verdana 1.25, неизвестные 1.08), поэтому подгонка и аудит переполнения консервативны.
- Офлайн-планировщик опирается на структуру брифа (заголовки разделов, предложения, числа, таблицы Markdown); свободный текст без структуры лучше планирует модель.
- SmartArt, видео и анимации шаблона не разбираются; слайды с ними не используются как образцы.
- Генерация изображений (задача со звёздочкой) в текущей версии не включена; в колоду попадают только ассеты самого шаблона.
- Хранилище файловое, очередь задач в процессе: сервис рассчитан на одного-нескольких пользователей, не на продакшен-нагрузку.
