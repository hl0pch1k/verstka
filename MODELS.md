# MODELS — модели, роли, требования

Все модели — только с открытыми весами и лицензией Apache 2.0 / MIT, не больше 35B параметров на модель. Закрытые API не используются нигде, в том числе на прототипе. Конфигурация ролей — `configs/models.yaml`; ключ провайдера — переменная окружения `OPENROUTER_API_KEY` (см. `.env.example`).

| Роль | Модель | Лицензия | Параметры | Где используется | Ссылка |
|---|---|---|---|---|---|
| `llm` | Qwen3.8-27B | Apache 2.0 | 27B, dense | классификация слайдов по JSON фигур, извлечение правил, реестр фактов, планирование, сокращение текста, проверка фактов, связность колоды, чат-агент | https://huggingface.co/Qwen/Qwen3.8-27B |
| `vlm` | Qwen3.8-27B (мультимодальная) | Apache 2.0 | 27B | проверка типа слайда по картинке, тегирование ассетов, 11 вопросов валидации контента по PNG слайда | та же модель |
| `llm` (запасная) | Qwen3.6-27B / Qwen3-32B | Apache 2.0 | 27B / 32B | то же, если основная недоступна | https://huggingface.co/Qwen |
| `t2i` (задача со звёздочкой, с 15 октября) | Z-Image-Turbo | Apache 2.0 | 6B | иллюстрации внутри слайда в палитре шаблона | https://huggingface.co/Tongyi-MAI/Z-Image-Turbo |
| `t2i` (качественный вариант) | Qwen-Image-2512 | Apache 2.0 | 20B MMDiT | то же | https://huggingface.co/Qwen/Qwen-Image-2512 |

Одна и та же модель для текста и картинок выбрана намеренно: Qwen3.8-27B — именно та модель, которую VK предоставляет финалистам через свой инференс. Переход на инференс VK — замена `base_url` и `api_key` в `configs/models.yaml`, код не меняется (`verstka/providers/openai_compat.py` работает с любым OpenAI-совместимым эндпоинтом: OpenRouter, vLLM, инференс VK).

## Что делает каждая модель в пайплайне

| Скилл | Роль | Вход | Выход |
|---|---|---|---|
| `slide_classifier` | llm | компактный JSON фигур слайда-образца + сводка шаблона | тип слайда, роли фигур, уверенность |
| `slide_vision_check` | vlm | PNG слайда-образца | тип слайда, назначение, уверенность |
| `asset_tagger` | vlm | картинка-ассет | тип (иконка/логотип/иллюстрация/фото/узор), теги |
| `rule_harvester` | llm | предложения-инструкции со слайдов шаблона | явные правила оформления |
| `data_extractor` | llm | бриф | реестр фактов, ряды, таблицы |
| `outline_planner` | llm | бриф, факты, доступные типы слайдов, стратегия | план колоды |
| `fact_checker` | llm | план + бриф + факты | несоответствия |
| `text_condenser` | llm | текст, лимит слов | сокращённый текст |
| `slide_content_audit` | vlm | PNG сгенерированного слайда + план + факты | ответы на 11 вопросов с обоснованием |
| `deck_coherence_audit` | llm | последовательность заголовков | проблемы связности, единый язык |

Промпты и параметры каждого скилла лежат отдельными файлами в `skills/<имя>/` и версионируются (см. `ARCHITECTURE.md`, раздел про версионирование). Все скиллы возвращают JSON по pydantic-схеме; невалидный ответ повторяется до трёх раз с текстом ошибки.

## Режим без моделей

Весь пайплайн работает без единого вызова модели (`--no-llm --no-vlm` или отсутствие ключа): классификация только эвристиками, планировщик по заголовкам и абзацам брифа с регулярными выражениями для чисел и markdown-таблиц, аудит только детерминированный. Так гарантируются воспроизводимые тесты и демонстрация без сети.

## Системные требования

- Python 3.11+, LibreOffice (`soffice`) и poppler (`pdftoppm`) для рендера и PDF.
- Инференс на отборочном этапе: любой OpenAI-совместимый провайдер с открытыми моделями (по умолчанию OpenRouter). Локально: vLLM с `Qwen/Qwen3.8-27B` требует GPU с ~60 ГБ VRAM в bf16 или ~20 ГБ в 4-битном квантовании; для CPU-демо используйте режим без моделей.
- Расход на одну колоду из 12 слайдов с моделями: разбор шаблона ~2 вызова на слайд-образец (кэшируется по хэшу), планирование 5–20 вызовов на три варианта, аудит моделями 12–15 вызовов на вариант; при ценах OpenRouter для `qwen/qwen3.8-27b` ($0.42 за миллион входных и $3.00 за миллион выходных токенов) — центы на колоду.
- Стоимость и токены каждого запуска пишутся в `run_manifest.json`.

## Бесплатный режим OpenRouter

У той же модели есть бесплатный вариант `qwen/qwen3.8-27b:free` (конфиг `configs/models.free.yaml`, включается строкой `VERSTKA_MODELS=configs/models.free.yaml` в `.env`). Лимиты OpenRouter для бесплатных моделей: 20 запросов в минуту и 50 запросов в сутки, либо 1000 в сутки, если на аккаунт когда-либо зачислено от 10 долларов. Клиент держит не больше 18 запросов в минуту и пережидает ответ 429; когда дневная квота исчерпана, все дальнейшие вызовы сразу уходят в детерминированные запасные шаги — генерация не падает. 50 запросов в сутки хватает на планирование нескольких генераций по уже разобранным шаблонам; разбор шаблона моделями и аудит моделями по картинкам требуют большей квоты.

Что выяснилось на живом ключе (23.09.2026):

- **JSON-режим.** С `response_format={"type": "json_object"}` бесплатный хост (ModelRun) портит структурный вывод: к значениям прилипает `": "`, ключи приходят пустыми. Без этого режима та же модель отвечает чистым JSON за 1 с. Поэтому в обоих конфигах OpenRouter стоит `json_mode: false`, а схема ответа и так передаётся в промпте. Для других бэкендов (например, инференса VK) действует страховка: первый же невалидный ответ в JSON-режиме переключает провайдера на обычный режим до конца прогона.
- **Ответ 429 «temporarily rate-limited upstream».** Это общая перегрузка бесплатной ёмкости, а не лимит аккаунта. Клиент пережидает её по 20 с и не тратит на это попытки. Собственные мгновенные повторы OpenAI SDK отключены (`max_retries=0`): они только расходуют квоту. Всеми повторами управляет `complete()`.
- **Тесты герметичны.** `tests/conftest.py` ставит `VERSTKA_NO_DOTENV=1`, и ключ из `.env` в тесты не попадает.
