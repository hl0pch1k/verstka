# Интерфейс «Слои»: новый веб-интерфейс Verstka

Дата: 2026-10-13. Ветка: `ui-sloi` (рабочая копия `verstka-dev/.worktrees/ui-sloi`). Владелец утвердил дизайн и
план («всё просто супер», «приступай»).

## 1. Цель и рамки

- **Цель.** Заменить веб-интерфейс `web/` дизайном «Слои» один к одному. Эталон — `docs/design/sloi/` (доски,
  снимки, живой прототип `boards/V2.dc.html`).
- **Старый интерфейс удаляется целиком.** Это все компоненты, старые токены Tailwind, View Transitions, шрифт
  Onest и сине-серая палитра VKUI. Смеси старого и нового нет.
- **Компромиссов с макетом нет.** Отличаться может только содержимое, потому что оно настоящее: слайды, тексты,
  оценки, замечания, время сборки. Тексты, придуманные для макета («Почему так» по слайдам, макеты шаблона,
  аккордеоны плана), заменяются данными сервера.
- **Одно сознательное улучшение относительно прототипа.** Помощник сужает колоду на ВСЕХ экранах. В прототипе на
  «Создать» и «Сборке» плита помощника ложилась поверх колоды. Здесь содержимое этих экранов становится резиновым
  и ничего не перекрывается.
- **Ширина.** Компьютер, от 1280 px; колода во всю ширину окна с полями 24 px, как на досках. Телефонные доски
  M-* остаются референсом на будущее, в эту работу не входят.
- **Сервер.** Почти не меняется: всё нужное API уже есть (см. раздел 5). Допустимы мелкие добавления. Например,
  поле `job_id` в мете генерации уже хранится — его нужно отдать в типах, чтобы после перезагрузки страницы
  вернуться к идущей сборке.

## 2. Что остаётся и что уходит

**Остаётся — «провода» без дизайна, проверенные тестами:**
- `src/api.ts`, `src/types.ts` (типы можно дополнять);
- `src/lib/*`:
  - отслеживание задач по SSE с опросом: `jobs.ts`, `jobState.ts`;
  - фазы агента и раскадровка: `agent.ts`, `stage.ts`;
  - тексты: `textFacts.ts`, `jobText.ts`, `modelText.ts`, `narrate.ts`, `plain.ts`, `reasons.ts`, `designEye.ts`,
    `pictures.ts`, `writerMode.ts`;
  - прочее: `templateFiles.ts`, `fonts.ts`, `utils.ts`, `flows.ts`;
  - все 41 тест в `lib/*.test.ts`.
- `src/store.tsx` — его слой данных: шаблоны, генерации, задачи, здоровье сервера, сообщения чата. Слой «экранов»
  переписывается под новую модель (раздел 4).
- `web/scripts/test.mjs`, `vite.config.ts`, `tsconfig.json`.

**Уходит:**
- `src/components/**` целиком (67 файлов);
- `src/dev/StageReplay.tsx` — переписывается под новый экран сборки, см. раздел 6;
- старый `src/index.css`, `tailwind.config.js` и `postcss.config.js` (Tailwind больше не нужен), Onest и JetBrains
  Mono в `index.html`;
- `lib/motion.ts` в части View Transitions. Нужное (`usePresence`, `decodeImage`, `useCountUp`) переносится.

**Что ещё зависит от старых файлов:**
- Python-тесты читают файлы веба:
  - `tests/unit/test_writer_mode.py` берёт `SAMPLE_BRIEF` из `NewGenerationFormParts.tsx`;
  - остальные (`test_model_status_api.py`, `test_writer_gate2.py`) читают `lib/modelText.ts` и `lib/writerMode.ts`,
    а эти файлы остаются.
- `SAMPLE_BRIEF` и константы формы (`SLIDES_MIN/MAX/DEFAULT`, `BRIEF_MIN`, `PURPOSES`) переезжают в
  `src/lib/createForm.ts`, тест переводится на новый путь.
- Комментарии в Python, которые ссылаются на старые файлы, обновляются.
- CI-проверка `curl / | grep -q Verstka` продолжает работать: заголовок страницы «Verstka».

## 3. Стили, шрифты, иконки

- **CSS переносится с досок почти дословно** — это единственный способ сохранить утверждённые отступы и анимации.
  Папка `src/styles/`:
  - `tokens.css` — цвета, кривая `--ease`, длительности;
  - `base.css` — классы `p2-*` эталона: плиты, кнопки, поля, переключатели, сегменты, плитки, исчезающие края
    `p2-fade`, `p2-on/off`, `p2-lay`;
  - `create.css` — классы `tt-/up-/an-/pv-/dl-/ct-/cp-/tx-`;
  - `build.css` — `bs-/bk-/bf-`;
  - `result.css` — `ra-/rk-/rf-/rd-/rp-/rt-/lb-`;
  - `details.css` — `dd-/dq-/dw-/da-/dpl-/dtp-/dpt-/df-/dl*`;
  - `layers.css` — `gh-/ga-`;
  - `helper.css` — `gho-/hp-`;
  - `offline.css` — `p2-offline`, `p2-l*`, `of-`.
- Классы из модулей прототипа (`tp-`, `tx-`, `bd-`, `rm-`, `rt-`, `dl-`, `of-`, `hp-`) переносятся из `boards/V2.dc.html`.
- В компонентах — `className` с этими классами. Инлайновые стили досок переносятся в `style` или в класс.
- **Шрифты** — Manrope 500/600/700 и Unbounded 600/700 через Google Fonts, как на досках. Шрифт шаблона для
  превью по-прежнему грузит `lib/fonts.ts`.
- **Иконки** — компонент `Icon` с путями из `tools/icons_lib.py` (сетка 24). Толщина линии выбирается по размеру по
  правилу эталона. `lucide-react` удаляется.

## 4. Устройство интерфейса

### 4.1 Модель экрана

Одно состояние `ui` (reducer в `store.tsx`), как в прототипе:
- `screen`: `create | build | result`;
- `open`: `tpl | text` — раскрытый шаг на «Создать»;
- `more` — «Все параметры» раскрыты;
- `sect`: `null | hist | tpls` — разделы из шапки;
- `sheet`: `null | quality | why | agent | plan | template | files` — лист «Подробнее»;
- `pattern`: номер слайда шаблона или null — слой «Слайд N шаблона»;
- `textLayer`, `lightbox`, `helper`, `note` (раскрытая таблетка), `remarks` (режим замечаний);
- `tplPreview`, `tplDelete`;
- `slide` и `variant` — текущий слайд и вариант результата. Это уже есть: `selectedSlide` и `activeStrategy`.

**Геометрия колоды** — чистая функция `deckGeometry(ui)`. Она возвращает `translateY` четырёх плит и видимость
шапок, полос и тел плит. Значения для каждого состояния — из V2 (`Y`):
- «Создать», открыт текст — 0 / 144 / 556;
- «Создать», открыт шаблон — 0 / 524 / 668;
- «Все параметры», сборка — 0 / 40 / 80;
- результат — плита 04 на 120;
- «Подробнее» — лист на 160;
- разделы — на 120.

Функция покрыта тестами.

### 4.2 Компоненты (`src/ui/`)

- **`shell/`:**
  - `AppShell` — шапка и обёртка колоды с колонкой помощника `hp-wrap`;
  - `Brand` — логотип: полоски и офлайн-режим с бегущими красными полосками и строкой статуса;
  - `Nav` — «Мои презентации», «Шаблоны», «Помощник»; кнопки с подсветкой `p2-nav-on`.
- **`deck/`:**
  - `Deck` — плиты `.p2-slot` с transform из `deckGeometry`;
  - `Plate`, `Strip` — свёрнутая полоса плиты.
- **`create/`:**
  - `TemplatePlate` — лента: 6 обложек, «Все шаблоны · ещё N», «Загрузить свой», таблетки «Слайды»;
  - `UploadZone`, `Analysis` — перетаскивание и разбор шаблона, шаги разбора;
  - `TextPlate` — поле, печатающаяся подсказка с курсором, «Из файла», разбор текста, счётчик, ошибки у поля;
  - `ImproveNote` — режим «Улучшить готовую»;
  - `ParamsPlate` — короткий ряд, стрелка под «03» и `ParamsAll` («Все параметры»).
- **`build/`:**
  - `BuildPlate` — фазы с перекатом названий, часы и прогресс;
  - `Storyboard` — эскизы, критик, переделанные, готовые превью;
  - `Roles` — 9 ролей агента со статусами;
  - `Failed` — «Сборка остановилась»: «Собрать ещё раз», «Вернуться к тексту».
- **`result/`:**
  - `ResultPlate` — таблетка уведомления с действиями, шапка рабочей области, `Stage` (слайд), `Film`
    (миниатюры), колонка `Aside`: заголовок, оценка, варианты, «Скачать», PDF, «Изменить текст», карточки, ссылки
    «План / Шаблон / Файлы»;
  - `RemarksPanel`, `StageMarks`, `FixSketch` — режим «Замечания» и исправление слайда;
  - `PictureCard` — изображение на слайде;
  - `CompactResult` — вид при открытом помощнике.
- **`layers/`:**
  - `Layer` — общий: подъём на 520 мс, лесенка `p2-ls`, при закрытии уезжает непрозрачным и с содержимым;
  - `HistoryLayer`, `TemplatesLayer`;
  - `TplPreviewLayer`, `TplDeleteDialog`;
  - `TextLayer`, `Lightbox`;
  - `DetailsSheet` и вкладки `tabs/Quality|Why|Agent|Plan|Template|Files`, `PatternLayer`.
- **`helper/`** — `HelperPlate`: лента, подсказки, поле, отправка в настоящий чат.
- **`kit/`** — общие мелкие детали: `Icon`, `Switch`, `Segmented`, `ScoreRing`, `Spinner`, `Menu`, `Collapse`,
  `usePresence` (держит содержимое смонтированным, пока идёт уход).

Ни один файл не превращается в «простыню»: компонент больше ~400 строк режется по смыслу.

### 4.3 Движение

- Переходы — CSS: `transition` и `keyframes` досок. React только переключает классы и `style.transform`.
- Удаление из DOM — только после окончания ухода (`usePresence`, 520 мс для слоёв, 240 мс для мелочей).
  Поэтому слои уезжают с содержимым.
- Последовательности из прототипа воспроизводятся:
  - открытие презентации из истории: плита результата поднимается снизу одним движением с плитами 02/03;
  - возврат на главный по логотипу;
  - «Все параметры»;
  - исправление слайда: сжатие в эскиз 520 мс, работа, разжатие;
  - смена фаз сборки.
- `prefers-reduced-motion`: длительности падают до 1 мс. Смысл состояний сохраняется.

## 5. Связь с сервером

| Состояние макета | Откуда данные |
|---|---|
| Лента шаблонов, «Шаблоны», «Слайды шаблона» | `GET /api/templates`, `GET /api/templates/{id}`, превью `files/thumbs/slide-NNN.jpg` |
| «Загрузить свой» → разбор | `POST /api/templates` → задача `analyze`; шаги разбора — сообщения задачи (`jobText.ts`) |
| Переименовать / удалить шаблон | `PATCH` / `DELETE /api/templates/{id}` |
| «Из файла» .txt/.md | Чтение файла в браузере (как сейчас), разбор `textFacts.ts` |
| «Улучшить готовую» (.pptx) | `POST /api/templates` с `improve=true` → `improve`, затем генерация с `improved_from` |
| Ошибки у поля | Клиентские правила (`BRIEF_MIN_TOPIC`, типы файлов `templateFiles.ts`) и ошибки сервера |
| Параметры | `GenerateRequest`: `slides`, `strategies`, `audience`, `purpose`, `use_models`, `audit_models`, `eyes`, `pictures` |
| Сборка | Задача `generate`: SSE `/api/jobs/{id}/events`. Фазы, раскадровка, критик — события агента (`agent.ts`, `stage.ts`). Превью — `…/{s}/slides`. Названия фаз — `STAGE_TITLE`. «Не получилось» — статус `failed` |
| Результат | `GET /api/generations/{gid}`: варианты, оценки, `slides`, `files` (pptx/pdf/html), `audit`, `design`, `agent`, `eyes`, `pictures`, `writer` |
| «Показать текст» | `writer.text`, `writer.sources`, `writer.pages`; «Изменить» → текст в поле «Создать» |
| «Замечания» → «Исправить слайд» | `audit.issues` по слайдам, `POST …/slides/{n}/fix` (`wishes`, `issue_ids`) → `SlideFixResult` |
| «Вернуть как было» | `POST …/edits` («верни как было») |
| Изображение на слайде | `variant.pictures`, `POST …/slides/{n}/image` (`generate` / `remove`) |
| «Подробнее» → Качество | `audit`: чипы, отметки, `POST …/fixes` (`issue_ids` / `all_deterministic`), `eyes` |
| Почему так | `variant.design`, `plan.slides[].reasons/alternatives`, критик; при нехватке — `GET …/explain/{n}` |
| Агент | `variant.agent` (лента, критик), `variant.edits` |
| План | `outline`, `layout_plan`, `writer`, реестр чисел, ряды диаграмм |
| Шаблон, «Слайд N шаблона» | Манифест шаблона: токены, палитра, `patterns` со слотами и превью, правила |
| Файлы | `files`, `run_manifest` (паспорт, `timings_s`, модели), JSON-файлы для разработчиков |
| «Мои презентации» | `GET /api/generations`; клик → `GET /api/generations/{gid}`; идущая — к задаче; неудачная — «Создать» с той же темой |
| Помощник | `POST /api/chat`; действия ответа (`generation_started`, `jobs`, `open_tab`, `edit`) открывают нужное место интерфейса |
| Нет связи | Опрос `/api/health`, как сейчас; без связи — режим логотипа и строка статуса |

После перезагрузки страницы во время сборки интерфейс возвращается к идущей задаче. Для этого серверу нужно отдать
`job_id` в `GET /api/generations/{gid}` — это единственная обязательная правка API.

## 6. Проверка

- `npm run build`: проверка типов и сборка без ошибок.
- `npm test`: 41 старый тест логики и новые тесты:
  - `deckGeometry`;
  - сопоставление событий задачи и шагов разбора;
  - правила ошибок поля;
  - лента шаблонов: свои первыми, выбранный всегда виден.
- Python:
  - `tests/unit` — полный прогон (~4 мин, 4 потока);
  - проверка, что тесты, читающие веб, видят новые пути;
  - `tests/integration` по правилам рабочей копии.
- **Вид.** Каждое состояние снимается в браузере (preview-инструменты, `verstka serve` на рабочей копии с настоящим
  `workspace`) и сверяется со снимками `docs/design/sloi/shots/`. Расхождения в вёрстке исправляются до совпадения.
- **Живые прогоны.** 1–2 настоящих сборки через Polza (≈8 ₽ за колоду): тема → сборка → результат → замечания →
  исправление слайда → «Подробнее» → помощник.
- `dev/StageReplay` переписывается: воспроизводит записанную сборку на новом экране сборки для проверки без
  затрат на модели.

## 7. Как ведётся работа

- Ветка `ui-sloi` в отдельной рабочей копии: в общей `verstka-dev` параллельно работают другие сессии.
- Коммиты на русском, только своими путями, без Co-Authored-By, без push. Перед коммитом — полный прогон тестов.
- Порядок:
  1. основа: стили, шрифты, иконки, оболочка, модель экрана, колода;
  2. «Создать»;
  3. «Сборка»;
  4. «Результат»;
  5. слои и «Подробнее»;
  6. помощник и нет связи;
  7. удаление старого, тесты, живые прогоны.
- Шаги 2–6 можно вести параллельно, когда основа готова.
- Слияние `ui-sloi` в `next` — после того, как владелец посмотрит готовый интерфейс.
