# ARCHITECTURE — пайплайн Verstka

Принцип продукта: **читать чужой шаблон как набор правил**. Источник правил — весь PPTX: мастера, макеты и, главное, обычные слайды. Сервис не привязан к трём выданным шаблонам: на входе может быть любой PPTX, в том числе нарисованный вручную поверх пустых слайдов без макетов.

```
PPTX ──► Ingest ──► Template Analysis ──► manifest.json (токены, паттерны, компоненты, ассеты, правила)
                                                 │
brief ──► Content Planning ──► outline.json ─────┤
                                                 ▼
                                Layout Matching ──► layout_plan.json (объяснимый выбор макета)
                                                 ▼
                                Rendering (clone | synth) ──► deck.pptx (нативные объекты)
                                                 ▼
                                Audit ──► audit_report.json ──► Autofix (≤ 2 итерации) ──► Audit
                                                 ▼
                                Export ──► .pptx  .pdf  .html      + run_manifest.json
```

Сквозные сервисы: `providers` (модели), `skills_registry` (версионируемые скиллы и агенты), `pipeline` (оркестрация, кэш, прогресс), `api` (FastAPI + чат-агент), `web` (React).

## Границы слоёв и контракты

| Слой | Пакет | Вход → выход | Ключевые решения |
|---|---|---|---|
| Ingest | `verstka/ingest` | PPTX → рабочая папка `workspace/templates/<sha256>/` с распакованным пакетом, PNG-рендерами (LibreOffice → PDF → poppler), медиа | Кэш по хэшу файла; рендер нужен для VLM и превью; тот же путь для «прошлой презентации» без макетов |
| Template Analysis | `verstka/analysis` | рабочая папка → `TemplateManifest` | см. ниже |
| Content Planning | `verstka/planning` | бриф + манифест + стратегия → `DeckOutline` (слайды, реестр фактов, ряды, таблицы) | Скиллы `data_extractor`, `outline_planner`, `fact_checker`, `text_condenser`; детерминированный запасной планировщик без моделей; валидация плотности (≤6 буллетов, ≤15 слов, таблица ≤7×5, ≤5 серий) |
| Layout Matching | `verstka/matching` | `DeckOutline` + манифест + стратегия → `LayoutPlan` | Детерминированный скорер с объяснениями на русском; порог синтеза; альтернативы для автофикса |
| Rendering | `verstka/rendering` | план + манифест → `deck.pptx` | Два рендерера с одним контрактом: клон образца (копия XML слайда в пакете шаблона) и синтез из токенов; нативные диаграммы и таблицы python-pptx; иконки из ассетов шаблона |
| Audit | `verstka/audit` | `deck.pptx` → `DeckIR` → `AuditReport` | Реестр проверок (`@check`), детерминированные и модельные; автофикс переводит находки в действия |
| Export | `verstka/export` | `deck.pptx` → PDF (LibreOffice), HTML (собственный рендерер из `DeckIR`: разметка, SVG-диаграммы, `<table>`, встроенные шрифты и картинки) | HTML — не скриншоты |

Все артефакты — pydantic-схемы в `verstka/schemas/` (`template.py`, `outline.py`, `layout.py`, `deck_ir.py`, `audit.py`), сериализуются в JSON и лежат рядом с колодой.

## Разбор шаблона (Template Analysis)

Почему не макеты: в выданных шаблонах 1621 свободная фигура против 81 привязанной к плейсхолдеру (VK Tech); имена макетов врут; нативных диаграмм нет ни в одном. Поэтому **единица анализа — слайд-образец**, а не макет.

1. **Извлечение фигур** (`analysis/shapes.py`): обход `spTree` с трансформациями групп, наследование размера/цвета/шрифта текста по цепочке ран → абзац → фигура → плейсхолдер макета → плейсхолдер мастера → `txStyles` → тема (`analysis/theme.py` резолвит `schemeClr`, `lumMod/lumOff/tint/shade`).
2. **Токены** (`colors.py`, `typography.py`, `spacing.py`, `chrome.py`): палитра с ролями (фон светлый/тёмный, поверхность, текст основной/вторичный, акценты, нейтральные; роли не взаимоисключающие — чёрный может быть и фоном титула, и цветом текста); семейства и шкала кеглей по статистике ранов (тема часто врёт: во всех трёх шаблонах VK тема пишет Arial, раны используют Play); безопасная область и колонки по перцентилям координат; хром — элементы, стоящие на одном месте на ≥40% слайдов, плюс логотипы и узоры из макетов и мастеров.
3. **Группы повторов** (`groups.py`): якоря — одинаковые фигуры/картинки; ячейка = якорь + фигуры внутри + «сателлиты» (текст справа или под якорем); ось (ряд, колонка, сетка), зазор, `max_n` по свободному месту. Это то, что даёт «карточки×N» с ресайзом под контент.
4. **Роли слотов и тип слайда** (`roles.py`, `kinds.py`, `classify.py`): ансамбль трёх сигналов — геометрические эвристики, LLM по компактному JSON фигур (`slide_classifier`), VLM по картинке (`slide_vision_check`); голоса взвешиваются, согласие пишется в манифест и влияет на качество паттерна.
5. **Паттерны** (`patterns.py`): слоты с ёмкостью в символах и строках (по метрикам шрифта), группы, декоративные ассеты, дедупликация одинаковых образцов.
6. **Компоненты, ассеты, правила** (`components.py`, `assets.py`, `rules.py`): спецификации карточки, буллета, цифры, иконки-чипа, стиля таблицы и диаграммы; извлечённые картинки с типами (иконка, логотип, иллюстрация, фото, узор); правила дизайнера, выписанные текстом на слайдах (например, в VK Education), плюс производные правила.

Результат виден человеку: `gallery.html` в рабочей папке шаблона и вкладка «Шаблон» в интерфейсе.

## Планирование

Бриф → `data_extractor` строит **реестр фактов** (каждое число с единицей, подписью и цитатой-источником), ряды для диаграмм и таблицы. `outline_planner` получает бриф, реестр, список типов слайдов, реально существующих в шаблоне (с максимальным числом повторов), целевое число слайдов и инструкцию стратегии; возвращает план, где каждый заголовок — вывод, а числа ссылаются на факты. `fact_checker` сверяет план с брифом; при ошибках планировщик перезапускается один раз с замечаниями. Инструкции пользователя («не более 5 слайдов») парсятся из брифа и обязательны.

## Подбор макета (Layout Matching)

Для каждого слайда плана и каждого паттерна шаблона считается балл:

`0.45·совместимость_типов + 0.25·ёмкость_ячеек + 0.10·помещаемость_текста + 0.05·семья + 0.10·качество − штраф_повтора − лишние_слоты + стиль_стратегии`, умноженный на вес стратегии при точном совпадении типа.

Таблица совместимости с запасными типами лежит в `matching/compat.py` (например, `stat_row → big_number → cards`). Для диаграмм и таблиц требуется крупная область; для цитат — большой текстовый слот без списка ячеек. Если лучший балл ниже порога стратегии, слайд уходит в синтез с композицией из фиксированного набора. Каждое решение сопровождается причинами на русском и списком альтернатив — их использует автофикс и чат-агент («почему слайд 4 такой»).

## Рендеринг

**Клон**: слайд-образец копируется внутрь пакета шаблона со всеми связями (картинки, гиперссылки), поэтому мастера, макеты, тема, встроенные шрифты и хром сохраняются. Дальше: текст в слоты с сохранением свойств ранов (один абзац на пункт, буллеты по шаблону), группы ячеек урезаются или дублируются вдоль оси (не выходя за край слайда), числа не объединяются, порядковые «01…06» подставляются в повестку и шаги, картинки-образцы без замены удаляются, боксы «Вставить фото/QR» удаляются, текст подгоняется по реальным метрикам Play (в комплекте, OFL) только по шкале шаблона, диаграммы и таблицы вставляются нативными объектами в область образца (нарисованные фигурами образцы графиков стираются).

**Синтез**: макет шаблона нужной семьи (фон и хром наследуются), заголовок в стиле титульных слотов образцов, композиции `bullets, cards, stat_row, big_number, two_column, comparison, process, agenda, chart_text, table, quote, image_text, section, thanks` из компонентов и токенов.

## Аудит и автофикс

См. `AUDIT.md`. Схема: `DeckIR` строится тем же экстрактором, что и разбор шаблона, поэтому аудит одинаково работает с нашими и чужими колодами. Детерминированные проверки — чистые функции с id, уровнем и предложением исправления; модельные — VLM по PNG слайда (11 вопросов из ТЗ) и LLM по последовательности заголовков. Автофикс: сильные дефекты вёрстки → перевыбор паттерна из альтернатив или синтез (полный ре-рендер, несколько секунд), лёгкие → уменьшение кегля, длинные буллеты → сокращение, чужой шрифт/цвет → замена в XML. Не более двух итераций и только пока число ошибок падает. Пользователь может применить выбранные исправления из интерфейса (`POST /api/generations/{id}/{strategy}/fixes`).

## Три варианта вёрстки

Ось различий — **композиционная стратегия** (`configs/strategies.yaml`): `structured` (одна мысль на слайд, разделители, списки и карточки), `visual` (числа крупно, ряды в диаграммах, тезисы под иконками, иллюстрации шаблона, выводы вперёд), `compact` (на треть меньше слайдов, две колонки, сравнения, таблицы). Стратегия меняет инструкцию планировщику, веса типов в матчере и тай-брейки выбора образцов; факты и правила шаблона одни для всех.

## Версионирование скиллов и агентов

Каждый скилл — папка `skills/<имя>/` с `skill.yaml` (версия, роль, схема ответа, параметры, changelog) и промптами в markdown; агенты — `agents/*.yaml`. Реестр считает sha256 содержимого. Каждая генерация пишет `run_manifest.json`: версии и хэши скиллов, модели и провайдер, хэши шаблона и брифа, тайминги стадий, применённые фиксы, сводка аудита, git-коммит. `GET /api/generations/{a}/{s}/diff/{b}/{t}` показывает, что изменилось между запусками — так видно, что результат поменялся из-за новой версии скилла.

## Отказоустойчивость и бюджет

Каждый слайд рендерится в `try/except`: клон не удался → синтез, синтез не удался → простейший список. Провайдер моделей недоступен → детерминированные планировщик, классификатор и аудит (весь пайплайн работает офлайн). Анализ шаблона кэшируется по хэшу и версии анализатора. Цель ≤ 5 минут на колоду: на трёх шаблонах VK три варианта с аудитом, автофиксом и экспортом собираются за 30–60 секунд без моделей.

## Границы, которые проверены тестами

`tests/unit/` — схемы, провайдеры, реестр скиллов, пакет, рендер, тема, фигуры, токены, группы, роли, классификация, паттерны, манифест, планировщик, матчер, рендеринг, аудит, экспорт, API. `tests/integration/` — три шаблона VK и отложенный «неизвестный» шаблон.
