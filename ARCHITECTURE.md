# ARCHITECTURE — пайплайн Verstka

Принцип продукта: **читать чужой шаблон как набор правил**. Источник правил — весь PPTX: мастера, макеты и, главное, обычные слайды. Сервис не привязан к трём выданным шаблонам: на входе может быть любой PPTX, в том числе нарисованный вручную поверх пустых слайдов без макетов.

```
PPTX ──► Ingest ──► Template Analysis ──► manifest.json (токены, паттерны, компоненты, ассеты, правила)
                                                 │
brief ──► Content Planning ──► outline.json ─────┤
                                                 ▼
                                Layout Matching ──► layout_plan.json (объяснимый выбор макета)
                                                 ▼
                                Rendering (compose | clone) ──► deck.pptx (нативные объекты)
                                                 ▼
                                Audit ──► audit_report.json ──► Autofix (≤ 2 итерации) ──► Audit
                                                 ▼
                                Export ──► .pptx  .pdf  .html      + run_manifest.json
```

Сквозные сервисы: `providers` (модели), `skills_registry` (версионируемые скиллы и агенты), `pipeline` (оркестрация, кэш, прогресс), `api` (FastAPI + чат-агент), `web` (React).

## Границы слоёв и контракты

| Слой | Пакет | Вход → выход | Ключевые решения |
|---|---|---|---|
| Ingest | `verstka/ingest` | PPTX → рабочая папка `workspace/templates/<sha256>/` с распакованным пакетом, PNG-рендерами (LibreOffice → PDF → poppler), медиа | Кэш по хэшу файла; рендер нужен для VLM и превью; тот же путь для «прошлой презентации» без макетов |
| Template Analysis | `verstka/analysis` | рабочая папка → `TemplateManifest` | см. ниже |
| Content Planning | `verstka/planning` | бриф + манифест + стратегия → `DeckOutline` (слайды, реестр фактов, ряды, таблицы) | Скиллы `data_extractor`, `outline_planner`, `fact_checker`, `text_condenser`; детерминированный запасной планировщик без моделей; валидация плотности (≤6 буллетов, ≤15 слов, таблица ≤7×5, ≤5 серий) |
| Layout Matching | `verstka/matching` | `DeckOutline` + манифест + стратегия → `LayoutPlan` | Детерминированный скорер с объяснениями на русском; порог синтеза; альтернативы для автофикса |
| Rendering | `verstka/rendering` | план + манифест → `deck.pptx` | Два рендерера с одним контрактом: композиция контентных слайдов по дизайн-системе шаблона (`compose.py`: сетка, шкала кеглей, карточка шаблона, крупные числа) и клон образца для обложек, разделителей и финала (копия XML слайда в пакете шаблона); нативные диаграммы и таблицы python-pptx |
| Audit | `verstka/audit` | `deck.pptx` → `DeckIR` → `AuditReport` | Реестр проверок (`@check`), детерминированные и модельные; автофикс переводит находки в действия |
| Export | `verstka/export` | `deck.pptx` → PDF (LibreOffice), HTML (собственный рендерер из `DeckIR`: разметка, SVG-диаграммы, `<table>`, встроенные шрифты и картинки) | HTML — не скриншоты |

Все артефакты — pydantic-схемы в `verstka/schemas/` (`template.py`, `outline.py`, `layout.py`, `deck_ir.py`, `audit.py`), сериализуются в JSON и лежат рядом с колодой.

## Разбор шаблона (Template Analysis)

Почему не макеты: в выданных шаблонах 1621 свободная фигура против 81 привязанной к плейсхолдеру (VK Tech); имена макетов врут; нативных диаграмм нет ни в одном. Поэтому **единица анализа — слайд-образец**, а не макет.

1. **Извлечение фигур** (`analysis/shapes.py`): обход `spTree` с трансформациями групп, наследование размера/цвета/шрифта текста по цепочке ран → абзац → фигура → плейсхолдер макета → плейсхолдер мастера → `txStyles` → тема (`analysis/theme.py` резолвит `schemeClr`, `lumMod/lumOff/tint/shade`).
2. **Токены** (`colors.py`, `typography.py`, `spacing.py`, `chrome.py`): палитра с ролями (фон светлый/тёмный, поверхность, текст основной/вторичный, акценты, нейтральные; роли не взаимоисключающие; поверхность карточки, почти сливающаяся с фоном, никогда не становится первым акцентом); фон-картинка даёт медианный цвет для решений о контрасте; семейства и шкала кеглей по статистике ранов (тема часто врёт: во всех трёх шаблонах VK тема пишет Arial, раны используют Play); безопасная область — по одному голосу на слайд (крайние координаты содержимого), чтобы листы с сотнями иконок не сжимали поля; хром — элементы на одном месте на ≥40% слайдов, логотипы и узоры макетов и мастеров, служебные плейсхолдеры (номер, дата, колонтитул) и **визуальный хром по рендерам**: контуры, стоящие на одном месте на большинстве отрендеренных слайдов (логотипы, зашитые в фоновые картинки, как в ЛЦТ).
3. **Группы повторов** (`groups.py`): якоря — одинаковые фигуры/картинки; ячейка = якорь + фигуры внутри + «сателлиты» (текст справа или под якорем); ось (ряд, колонка, сетка), зазор, `max_n` по свободному месту. Это то, что даёт «карточки×N» с ресайзом под контент.
4. **Роли слотов и тип слайда** (`roles.py`, `kinds.py`, `classify.py`): ансамбль трёх сигналов — геометрические эвристики, LLM по компактному JSON фигур (`slide_classifier`), VLM по картинке (`slide_vision_check`); голоса взвешиваются, согласие пишется в манифест и влияет на качество паттерна. Пустая рамка (светлая заливка или контур, внутри ничего нет) — слот-контейнер: текст пишется в саму фигуру, таблица или диаграмма встаёт внутрь.
5. **Паттерны** (`patterns.py`): слоты с ёмкостью в символах и строках (по метрикам шрифта), группы, декоративные ассеты и места крупных декоративных картинок, id хрома образца, дедупликация одинаковых образцов. Справочные слайды шаблона (листы иконок и логотипов, палитра HEX, список ссылок, листы графики) помечаются `reference` и в подбор не идут.
6. **Компоненты, ассеты, правила** (`components.py`, `assets.py`, `rules.py`): спецификации карточки, буллета, цифры, иконки-чипа, стиля таблицы и диаграммы; извлечённые картинки с типами (иконка, логотип, иллюстрация, фото, узор); правила дизайнера, выписанные текстом на слайдах (например, в VK Education), плюс производные правила.

Результат виден человеку: `gallery.html` в рабочей папке шаблона и вкладка «Шаблон» в интерфейсе.

## Планирование

Без модели работает детерминированный планировщик (`planning/heuristics.py` + `basic_outline`): разделы брифа → шаги («Неделя 1: …» → процесс), пары «Название: текст» → карточки, перечисления → карточки или процесс, три и больше чисел → ряд KPI с короткими подписями, таблицы → диаграмма (временной ряд — столбцы, сравнение — полосы) или таблица, остальное → тезисы с заголовком-выводом; хвосты раздела — в подзаголовок и заметки докладчика. С моделью: бриф → `data_extractor` строит **реестр фактов** (каждое число с единицей, подписью и цитатой-источником), ряды для диаграмм и таблицы. `outline_planner` получает бриф, реестр, список типов слайдов, реально существующих в шаблоне (с максимальным числом повторов), целевое число слайдов и инструкцию стратегии; возвращает план, где каждый заголовок — вывод, а числа ссылаются на факты. `fact_checker` сверяет план с брифом; при ошибках планировщик перезапускается один раз с замечаниями. Инструкции пользователя («не более 5 слайдов») парсятся из брифа и обязательны.

**Верность брифу** (`planning/grounding.py`, `planning/plan_json.py`). Ответ модели разбирается терпимо (раздел с содержанием получает тип по содержанию, пропущенный заголовок берётся из раздела; сырой ответ сохраняется в `planner_raw.json`), затем каждый план модели проходит детерминированную проверку по тексту брифа: каждая цифра (в заголовках, тексте, карточках, подписях, таблицах, метках разделов) должна быть цифрой брифа по значению или простой производной двух его цифр одной меры (разность, процент изменения, кратность); выдуманная цифра уходит вместе со своей фразой, слайд без содержания — целиком; «вырос / сократилось» допускается, только если бриф говорит об изменении этой величины (было/стало, до/после, с…до, вместо, против, периоды); единицы — как в брифе (NPS без %); заглушки контактов, графики без данных, пустые колонки и слайды, чьи слова в основном не из брифа, удаляются; заголовок колоды — из брифа. Число слайдов в промпте — потолок, а не цель: короткий бриф даёт короткую честную колоду. После проверки план доводится (`polish_plan`): в короткой колоде нет разделителя на каждый слайд, строка с одной цифрой становится крупной цифрой, подписи совпадают с тем, что покажет слайд. При вёрстке `rendering/fallbacks.py` страхует: график без данных или пустые колонки никогда не превращаются в пустой слайд.

Ответ модели проверяется, прежде чем стать планом: пустой план, план без содержательных слайдов и отказ («error», «Невозможно сформировать план…») отклоняются, и слайды планирует детерминированный путь. Если модель ответила одному варианту, а двум другим нет (перегруженный бесплатный хост), неудачные варианты берут её план, перестроенный под свою стратегию (`adapt_outline`: без разделителей у «Визуального» и «Компактного», числа — рядами KPI, «Компактный» сжат до своей цели). Бриф без заголовка получает название из первого утверждения; тема без тезисов («итоги пилота за квартал») становится **каркасом**: титул, повестка и разделы, обычные для такого типа презентации, с подсказками в заметках. Факты не придумываются. Кто составил план, записано в `outline.json` → `planned_by`: `model`, `rules`, `shared:<вариант>` или `skeleton`. Интерфейс об этом говорит: «Это каркас…», «Модель сейчас не ответила — план составлен встроенным планировщиком».

## Подбор макета (Layout Matching)

Для каждого слайда плана и каждого паттерна шаблона считается балл (справочные слайды и титулы с заголовком, зашитым в картинку, получают 0; слайдам с данными ёмкость — это свободная площадь под объект; обложкам — крупность заголовка):

`0.45·совместимость_типов + 0.25·ёмкость_ячеек + 0.10·помещаемость_текста + 0.05·семья + 0.10·качество − штраф_повтора − лишние_слоты + стиль_стратегии`, умноженный на вес стратегии при точном совпадении типа.

Таблица совместимости с запасными типами лежит в `matching/compat.py` (например, `stat_row → big_number → cards`). Для диаграмм и таблиц требуется крупная область; для цитат — большой текстовый слот без списка ячеек.

**Кто рендерит слайд.** Обложка, разделители и финальный слайд клонируются из образцов шаблона (на них держится узнаваемость: 3D-объекты, фото, хром). Контентные слайды по умолчанию **компонуются** (`compose_content: true` в стратегии): образец шаблона хорош как источник стиля, но плох как форма — его карточки такой высоты, какая была нужна дизайнеру, текст такой мелкий, какой допускает заглушка. Балл образцов всё равно считается: ближайший образец записывается в причины («ближайший образец — слайд 20 шаблона») и в альтернативы, а порог `clone_fit` позволяет вернуть клонирование образцов, подходящих без зазоров. Каждое решение сопровождается причинами на русском — их показывает вкладка «Почему слайд такой» и чат-агент.

## Рендеринг

**Клон**: слайд-образец копируется внутрь пакета шаблона со всеми связями (картинки, гиперссылки), поэтому мастера, макеты, тема, встроенные шрифты и хром сохраняются. Дальше: текст в слоты с сохранением свойств ранов (один абзац на пункт, буллеты по шаблону), группы ячеек урезаются или дублируются вдоль оси (не выходя за край слайда), числа не объединяются, порядковые «01…06» подставляются в повестку и шаги, картинки-образцы без замены удаляются, боксы «Вставить фото/QR» удаляются, текст подгоняется по реальным метрикам Play (в комплекте, OFL) только по шкале шаблона, диаграммы и таблицы вставляются нативными объектами в область образца (нарисованные фигурами образцы графиков стираются).

Группы ячеек перетекают по пролёту (строки и колонки карточек растягиваются или сужаются до 60%, не заходя на соседние элементы); роли фигур в ячейке берутся от самой фигуры или от той, с которой снята копия; заголовок на плашке растёт вместе с плашкой до ближайшего препятствия (логотипы включительно); текст в карточке занимает её высоту; один кегль на роль во всех карточках; пустые плашки, сироты-подложки, QR-коды шаблона и чужие гиперссылки убираются.

Типографика: высота строки при подгонке — межстрочный интервал шаблона × 1,2 em; размеры берутся из всех размеров, реально встречающихся в шаблоне, а не только из шкалы ролей; редкий текст на большой площади растёт до читаемых 16 пт (ниже заголовка). Число в карточке набирается крупно (≈2,4× подписи, в одну строку, акцентным цветом вместо приглушённого серого) и переносится в текстовое поле, если строка подписи для него мала. Сетка, в которой остаётся меньше ячеек, перестраивается целыми рядами (3×2 с четырьмя числами → 2+2); зигзаг ячеек (дорожная карта ЛЦТ) не берётся для меньшего числа пунктов. Кольца-инфографика, нарисованные картинками, не врут: для процента на их месте рисуется нативная кольцевая диаграмма с настоящим значением, другое число ставится без кольца. Заголовки и пункты обрезаются по границе фразы (никогда не на «за», «в», «и»); пункт, повторяющий заголовок-утверждение, убирается.

**Композиция** (`rendering/compose.py`, вызывается из `rendering/synth.py`) — вёрстка контентного слайда по дизайн-системе шаблона:

1. **Решения на всю колоду** (`deck_style`): семья фона (преобладающая среди контентных образцов), способ заголовка и его кегль. Если в большинстве образцов заголовок стоит на плашке (ЛЦТ), плашка становится рубрикой: в ней название раздела (капсом, если так в образцах), утверждение — крупным заголовком под ней; короткий заголовок-тема идёт в саму плашку. Иначе заголовок один кегль на всю колоду, ширина — всё свободное место полосы до логотипов.
2. **Холст**: самый чистый образец той же семьи, очищенный до фона, хрома и заголовка; отбрасываются образцы, чей макет рисует коллажи или панели в области контента, и образцы с арт-фоном. Для слайда с одной мыслью (утверждение, крупное число, цитата, пара тезисов) в «Визуальном» варианте — **арт-холст**: образец с фирменной графикой сбоку (3D-объекты VK Tech и WorkSpace, городской рендер ЛЦТ в фоновой картинке, коллаж Education); графика остаётся, контент встаёт на свободную сторону; не чаще одного слайда из трёх. Арт — это повторяющаяся графика шаблона (картинка на нескольких слайдах, общий макет, фон), а не разовый скриншот в телефоне.
3. **Сетка**: левый край — край текста заголовка (или плашки), правый — зеркало левого поля страницы в пределах безопасной области (на арт-холсте колонка идёт от графики до правого поля); верх — под заголовком и под линейкой макета, если она есть; низ — над логотипами и подвалом; один межколонный интервал. Арт-холст берётся, только если заголовок помещается в свободную колонку в три строки кеглем колоды.
4. **Шкала кеглей** (`Kit`): текст, лид, заголовок блока, крупное утверждение — ближайшие размеры шаблона с минимумами от высоты слайда (текст ≥ 2,5 % высоты); жирный — только если шаблон им пользуется. Числа — отдельная ступень: чем их меньше на слайде, тем крупнее (одно — до 30 % высоты слайда), в одну строку, один размер на ряд; крупная цифра сдвигается на свою боковую выносную область и на пустоту над цифрами, чтобы по краске стоять на левом крае и верхней линии контента. Утверждение и цитата — на ступень ниже заголовка слайда (не больше 0,9 его кегля), чтобы не перевернуть иерархию.
5. **Компоненты**: карточка — копия фигуры-карточки из ячеек образцов (заливка, контур, скругление, эффекты; абсолютный радиус угла сохраняется); цвета заголовков, текста и чисел — из слотов образцов с проверкой контраста; разделители — нейтральный цвет палитры.
6. **Композиции**: карточки (сетка 2–8, номер/индекс/число сверху, высота по самому длинному содержимому), ряд KPI, крупное число с пояснением, список с разделителями, утверждение с акцентной чертой или в карточке, этапы на оси, повестка, колонки сравнения, таблица (`tables.measure_table`: один кегль на все таблицы колоды, маленькая таблица — кеглем лида, колонки по содержанию, строки растут почти до двух третей области), диаграмма с выводом (коэффициент роста или прирост считается из ряда, не придумывается; последнее значение не повторяется — его уже показывает столбец; словесная единица «тыс.» пишется один раз над диаграммой, подписи — голые числа одной шкалы), цитата с висячей кавычкой. Размер текста подбирается под место: крупнейший, при котором всё читается (заголовок карточки ≤ 3 строк, текст ≤ 7); блок встаёт в оптический центр, если не заполняет область.
7. **Типографика**: неразрывные пробелы после предлогов, перед тире, внутри «12 400» и «27 млн ₽», между числом и существительным («4 сервера»); короткое составное слово не рвётся по дефису («GPU-сервера», «контакт-центра» — невидимый WORD JOINER, в Play нет неразрывного дефиса); перенос в измерителе — только по обычным пробелам, как в PowerPoint; подпись числа не повторяет заголовок, главная цифра визуального варианта не повторяется на соседних слайдах.

Без подходящих образцов (шаблон из одних макетов) композиция идёт на макете нужной семьи с плейсхолдером заголовка.

## Аудит и автофикс

См. `AUDIT.md`. Схема: `DeckIR` строится тем же экстрактором, что и разбор шаблона, поэтому аудит одинаково работает с нашими и чужими колодами. Детерминированные проверки — чистые функции с id, уровнем и предложением исправления; модельные — VLM по PNG слайда (11 вопросов из ТЗ) и LLM по последовательности заголовков. Автофикс: сильные дефекты вёрстки клона → перевыбор паттерна из альтернатив или композиция (полный ре-рендер, несколько секунд; скомпонованный слайд обратно в клон не переводится), лёгкие → уменьшение кегля, длинные буллеты → сокращение, чужой шрифт/цвет → замена в XML. Не более двух итераций и только пока число ошибок падает. Пользователь может применить выбранные исправления из интерфейса (`POST /api/generations/{id}/{strategy}/fixes`).

## Три варианта вёрстки

Ось различий — **композиционная стратегия** (`configs/strategies.yaml`): `structured` (одна мысль на слайд, разделители, списки с разделителями, карточки с индексами «01», таблицы), `visual` (числа крупно, тезисы — карточками с номерами, диаграмма с выводом, арт-холсты шаблона для слайдов с одной мыслью, выводы вперёд), `compact` (на треть меньше слайдов, две колонки, сравнения, таблицы, без украшений). Стратегия меняет инструкцию планировщику, веса типов в матчере и приёмы композиции; факты и правила шаблона одни для всех.

## Версионирование скиллов и агентов

Каждый скилл — папка `skills/<имя>/` с `skill.yaml` (версия, роль, схема ответа, параметры, changelog) и промптами в markdown; агенты — `agents/*.yaml`. Реестр считает sha256 содержимого. Каждая генерация пишет `run_manifest.json`: версии и хэши скиллов, модели и провайдер, хэши шаблона и брифа, тайминги стадий, применённые фиксы, сводка аудита, git-коммит. `GET /api/generations/{a}/{s}/diff/{b}/{t}` показывает, что изменилось между запусками — так видно, что результат поменялся из-за новой версии скилла.

## Рендер превью и экспорт

LibreOffice запускается один раз на колоду: из одного PDF получаются и экспорт, и превью слайдов; три варианта экспортируются параллельно. В цикле аудита без модельных проверок LibreOffice не нужен вовсе — детерминированные проверки работают по XML. LibreOffice получает копию пакета с очищенными подсказками плейсхолдеров макетов (иначе он показывает «Образец текста» там, где образец закрывал их карточкой); файл пользователя не меняется.

## Отказоустойчивость и бюджет

Каждый слайд рендерится в `try/except`: клон не удался → синтез, синтез не удался → простейший список. Провайдер моделей недоступен → детерминированные планировщик, классификатор и аудит (весь пайплайн работает офлайн). Перегруженный хост модели (429 «rate-limited upstream» дважды подряд) на 2 минуты считается недоступным: запросы не отправляются, и колода собирается за ~20 с, а не за весь бюджет ожидания; ожидание места в поминутном лимите тоже не выходит за бюджет генерации (`limits.time_budget_s`, 210 с). Анализ шаблона кэшируется по хэшу и версии анализатора. Цель ≤ 5 минут на колоду: на трёх шаблонах VK три варианта с аудитом, автофиксом и экспортом PPTX/PDF/HTML собираются за 8–25 секунд без моделей (разбор шаблона кэширован); холодный разбор шаблона ЛЦТ с рендером 37 слайдов — около минуты.

## Границы, которые проверены тестами

`tests/unit/` — схемы, провайдеры, реестр скиллов, пакет, рендер, тема, фигуры, токены, группы, роли, классификация, паттерны, манифест, эвристики брифа, планировщик, матчер, рендеринг, аудит, экспорт, API, дефекты обобщаемости (`test_generalisation.py`). `tests/integration/` — три шаблона VK и два невиданных: шаблон ЛЦТ и колода, нарисованная вручную без макетов.
